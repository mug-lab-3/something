# ファイル・フォルダの属性

`$STANDARD_INFORMATION` の値のオフセット `0x20` にある32ビットの属性を、ファイル本体の `StandardFileAttributes` として保存します。ファイル・フォルダの両方が対象です。ファイル参照のレコード番号・シーケンス番号で識別する観測に属し、ハードリンク名ごとには判定を変えません。

- `Hidden`（`0x2`）と `System`（`0x4`）は独立したビットです。両方が付く状態も保持します。
- 「通常」は両ビットがオフという意味です。`Normal`（`0x80`）が付いていることを要求しません。
- 欠落・曖昧な属性は `null` です。ゼロや通常属性に置き換えません。`IsHidden` と `IsSystem` も不明なら `null` を返します。
- `$FILE_NAME` の属性は名前ごとの元の記録として保持します。キャッシュの値で本体の属性を補完しません。
- 容量が未解決でも、有効なベースレコードから属性を取得できた場合は保存します。容量の確定状態とは別の情報です。
- ファイル／フォルダの区別にはMFTレコードのディレクトリフラグを使い、DOS属性のビットから作り直しません。

パーサーは常駐・無名の48バイト／72バイト形式を対象とし、その他の長さ、非常駐、有名、属性フラグ付きの形式を拒否します。ファイル組み立て時の重複も拒否します。未定義のDOS属性ビットはそのまま保存します。入力バッファは変更しません。スキャン時点の楽観的な観測であり、現在のWindows属性との完全な同時一致は保証しません。

## 保存形式

共有履歴は `catalog-v4.duckdb`、形式識別子4です。単独スキャン用DuckDBの形式識別子は3です。未リリースのため、新しい初期スキーマとEFのモデルスナップショットを更新し、旧DBを読み替える移行処理は設けません。旧ファイルは残りますが、新形式の履歴は再スキャンから始まります。

`observation`／`state_observation` のnullable属性フィールドが正本です。アプリ内の型は `uint?`、DBは範囲を制約した `BIGINT` です。高速な一覧用の `browser`／`shared_entry` にも同じ値を持たせます。属性だけが変わった場合も新しい観測状態と一覧を作り、変更前の履歴を維持します。同じ属性の次のスキャンでは状態を再利用します。追加のHidden/System列は保存せず、ビットから導出します。

読み出しは `ReadFiles` と `ReadFolderEntries` から属性と不明状態を取得できます。

## 表示・集計の設定

タブ右側の歯車メニューで「システムフォルダ・ファイルを含める」「隠しフォルダ・ファイルを含める」を切り替えます。初期値は両方オンです。設定はドライブ共通で、`%LOCALAPPDATA%/Something/display-settings.json` に保存します。デモ・画面テストでは実ユーザーの設定を読み書きしません。

- 設定はツリー、フォルダ内一覧、容量分析、比較前後の集計に適用します。ページ送り・ソート・件数の計算より先に除外します。
- 除外したフォルダは、その配下も対象外にします。ドライブのルート自体は除外しません。
- 両ビットが付いたファイルは両方の設定がオンの場合だけ対象です。属性不明は表示に残し、容量未解決や階層不明を既知ゼロに変えません。FILE_NAMEの属性からの補完もしません。
- ハードリンクは表示対象に残った名前ごとに計上します。除外フォルダ側の名前だけが対象外になり、通常フォルダ側の名前は残ります。DOS別名やリンク先の追跡については既存の集計方針を維持します。
- 比較前後には同じ設定を適用します。属性や親フォルダの変化により表示対象が変わった場合は、片側のみの観測として扱い、削除や容量ゼロとは断定しません。
- **スキャン・DB保存・履歴の保持と削除は設定にかかわらず全件が対象です。** 設定を戻すための再スキャンは不要です。ドライブカードの総容量・空き容量は実ボリュームの値です。

全件表示は既存のDB読み取り経路を使います。除外がある場合だけ、保存済みの観測からメモリ上の読み取り用集計を作ります。全ファイルのストリームモデルは保持せず、フォルダの集計と除外参照を保持し、フォルダ内一覧のキャッシュは直近の1フォルダ分に限定します。同じ条件のページ送りではソート結果を再利用します。設定変更時と別のスキャンを開く際には、この再集計の待ち時間が発生する場合があります。DBへのフィルター済み集計の書き戻しやバックグラウンド監視はしません。

合成データで属性の4通り、配下の除外、ルートの維持、属性不明、未解決容量、参照再利用、ハードリンクとDOS別名、300件のページ送り、並び順、キャンセル、設定の保存、履歴に全件が残ること、比較前後の同条件適用を検証します。

## 根拠と検証

Microsoftの [STANDARD_INFORMATION](https://learn.microsoft.com/en-us/windows/win32/devnotes/standard-information) は常駐の基本属性であることを示しています。Microsoftの公開定義で予約扱いの先頭部分のレイアウトは、libfsntfsの[形式調査資料](https://github.com/libyal/libfsntfs/blob/main/documentation/New%20Technologies%20File%20System%20%28NTFS%29.asciidoc) と照合しました。実装コードの移植はしていません。

合成バイナリで両形式、長さ境界、属性の重複、非対応形式、入力の不変性、FILE_NAMEとの不一致を検証します。DBテストではフォルダ・ファイル・別名、不明と既知ゼロ、全32ビット、属性だけの変更、履歴の不変性、未変更時の共有、一覧からの読み出しを検証します。新しい属性についての実ボリュームとの照合は未実施です。
