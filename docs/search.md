# 履歴の絞り込み検索

> [!NOTE]
> 画面とグラフは実装済みで、デモの履歴を使った画面のテスト（`--smoke-search`）で、条件画面・結果画面・グラフの表示を確認しました。実際のボリュームの履歴での確認と、グラフの背景色（画像では黒く写りますが、画像化の影響かは未確認です）は、実機で確認してください。

指定した日時の範囲にある 1 ドライブ分のスキャンを調べ、条件を満たすファイル・フォルダーをフォルダー階層のツリーで表示します。項目ごとに、範囲内の各スキャンでのサイズの推移を別ウィンドウのグラフで確認できます。

## 決定事項

| 項目 | 内容 |
| --- | --- |
| 対象 | フォルダーとファイルの両方。下の条件はすべて実装する |
| ドライブ | 1 回の検索で 1 ドライブ。ドライブをまたいだ検索はしない |
| 評価の時点 | サイズなどの値の条件は、範囲内で最後のスキャンの値で評価する |
| 日時の条件 | 作成日時・更新日時での絞り込みはしない |
| 画面 | 新しいタブ「検索」（タブの並びの最後）。条件画面と結果画面を切り替える。結果画面はファイル・容量分析タブと同じツリーと一覧の構成 |
| 実行 | 検索ボタンか Enter で実行する。条件を変えただけでは実行しない |
| グラフ | 1 項目につき 1 ウィンドウ |

## 範囲とスキャンの集合

開始と終了の日時を指定します。その範囲に完了した、退役していないスキャンを集合 S とし、S のうち最新のものを L（最後の時点）、最古のものを F とします。期間のボタン（直近 7 日・30 日・90 日・1 年）は、[履歴タブ](history.md#手動で履歴を削除する)と同じく入力欄を変えるだけです。既定は直近 30 日です。日時は分単位で、終了は、いま完了したスキャンも含むよう次の分までにします。

[保持規則](history.md#識別と保持)により、7 日より前の範囲は 1 日 1 スキャンに間引かれています。そのため、古い範囲ほど S の点の間隔は粗くなります。S が空の場合は検索しません。S が 1 件だけの場合は、変動に関する条件を評価できないことを示します。

## 項目の単位

ファイル・フォルダーは、既存の比較と同じく MFT 番号とシーケンス番号の組で照合します。サイズは[名前別容量](capacity-accounting.md#2-つの集計ポリシー)です。ハードリンクの各名前はそれぞれ 1 項目とし、DOS 別名は別の項目にしません。

範囲内での名前の変更や移動は、次のように扱います。

- 名前が 1 つのファイルとフォルダーは、名前の変更や移動があっても同じ項目として扱う。
- 名前が複数あるファイル（ハードリンク）は、名前が変わると、どの名前がどれに対応するかを特定できない。そのため、親フォルダーと名前の組が一致する名前だけを同じ項目とし、変わった名前は「消失」と「出現」として扱う。推測で対応付けることはしない。
- 名前が 1 つかどうかは、同じ識別子の名前の観測期間が重なるかどうかで判定する。名前を A→B→A と戻した場合も期間が重なるため、ハードリンクと同じく別の項目として扱う。

## 絞り込み条件

| 分類 | 条件 |
| --- | --- |
| 対象 | フォルダー／ファイル／両方 |
| 名前・パス | 部分一致、ワイルドカード、正規表現、拡張子、起点フォルダー（その配下のみ）、深さ |
| 属性 | 隠し・システム・圧縮・スパースなど、名前付きストリームを持つ |
| サイズ | L での最小・最大（論理／割り当て） |
| 変動 | F から L への増減（量・率）、S 内の最大と最小の差、単調増加・単調減少 |
| 存在 | S のすべてにある、途中から出現した、途中で消失した |

条件はすべて AND で組み合わせます。OR・NOT と条件の保存は、最初の版には含めません。

- 名前・パスの照合では、大文字と小文字を区別しません。DOS 別名は照合の対象にしません。
- 属性が不明な項目は、属性の条件のどちら側（「隠し」「隠しでない」など）にも一致させず、「属性不明」として別に件数を示します。
- 増減は L − F です。範囲内の累積や一時的なピークではありません（[比較の注意](capacity-accounting.md#比較の注意)と同じ意味です）。増減率の基準である F のサイズが 0 または未解決の場合、率は「—」とし、率の条件には一致させません。
- 「途中で消失した」項目は L に存在しないため、値の条件には最後に観測したスキャンの値を使います。
- 未解決のサイズや観測できなかったスキャンを、0 バイトや削除済みとは見なしません。サイズが未解決の項目はサイズの条件を満たさないものとして扱い、結果からは除かずに印を付けて残します。

### 表示設定との関係

属性の条件を指定しない場合は、設定の「システムファイルとフォルダー」「隠しファイルとフォルダー」の除外を、[ほかのタブ](capacity-accounting.md#表示対象の属性)と同じく結果にも適用します。除外した項目とその配下は結果に出しません。属性の条件を指定した場合は、表示設定を無視して、条件に一致した項目を表示します。

> [!NOTE]
> ほかのタブとは異なり、除外した項目の分をフォルダーのサイズから差し引くことはしません。フォルダーのサイズと増減は、常に除外なしの値です。範囲内のスキャンごとに集計し直すと、世代ごとに全件を読む必要があり、検索が非常に遅くなるためです。祖先のフォルダーの属性は、そのフォルダーを最後に観測したスキャンの値で判定します。

## 画面の構成

検索タブは、条件画面と結果画面を切り替えて使います。2 つを同時には表示しません。ドライブは、ほかのタブと共通のドライブ選択を使います。

```mermaid
flowchart LR
    Conditions[条件画面] -- 検索ボタン / Enter --> Results[結果画面]
    Results -- 条件に戻る --> Conditions
```

### 条件画面

タブの領域全体を使い、すべての条件を常に表示します。折りたたみはしません。

| 区分 | 入力 |
| --- | --- |
| 範囲 | 開始と終了の日時。[履歴タブ](history.md#手動で履歴を削除する)と同じ部品で、期間のボタンは入力欄を変えるだけ。範囲内のスキャンの件数と、F・L の日時を入力に合わせて表示する |
| 対象 | フォルダー／ファイル／両方 |
| 名前・パス | 名前と照合の方法（部分一致・ワイルドカード・正規表現）、拡張子、起点フォルダー、深さの最小・最大 |
| 属性 | 隠し・システム・圧縮・スパース・名前付きストリームのそれぞれに「指定なし／あり／なし」 |
| サイズ | 最小・最大と単位、論理サイズと割り当てサイズのどちらで評価するか |
| 変動 | 増減の最小・最大と単位、増減率の最小・最大、振れ幅（最大と最小の差）の最小、傾向（指定なし／単調増加／単調減少） |
| 存在 | 指定なし／すべてにある／途中から出現／途中で消失 |

最小が最大を超える、正規表現が正しくない、範囲内にスキャンがない、といった場合は、該当する入力の近くに理由を示し、検索を実行できないようにします。「条件をクリア」で、範囲以外の条件を初期値に戻します。

### 結果画面

上部に「条件に戻る」ボタン、検索した条件の要約、件数を表示します。件数は、一致したフォルダーとファイルの数に加えて、属性不明とサイズ未解決の数も分けて示します。その下に、ツリーと一覧を置きます。

条件の要約は、検索を実行した時点の条件を表示し、あとから変わることはありません。

- 先頭に範囲（実際に使った F と L の日時）を置き、続けて指定した条件だけを「サイズ ≥ 1 GiB」「隠し: なし」のような短い札で 1 行に並べる。「指定なし」の条件は出さない。
- 1 行に収まらない場合は、収まらない分を「+3」のようなボタンにまとめ、押すと全条件の一覧を表示する。
- 要約は表示専用で、ここから条件は編集しない。編集は「条件に戻る」から行う。

| 部分 | 内容 |
| --- | --- |
| ツリー（左） | 検索結果のフォルダー階層 |
| 一覧（右） | ツリーで選んだフォルダーの検索結果。「戻る」「進む」「上へ」とパスの表示もほかのタブと同じ |

検索の実行中は、既存の規則に従って読み込みアニメーションを表示し、キャンセルできるようにします。

### 画面の切り替え

- 「条件に戻る」で条件画面に戻っても、入力した条件と前回の結果は残す。条件を変えていなければ、「結果に戻る」で再検索せずに結果画面へ戻れる。条件を変えた時点で前回の結果は破棄する。
- 結果画面でドライブを切り替えた場合は、結果を破棄し、条件を残したまま条件画面に戻る。
- 結果画面でのマウスの戻るボタンや Alt＋← は、ほかのタブと同じくフォルダーの閲覧履歴に使う。条件画面へは「条件に戻る」ボタンでだけ戻る。

### ツリー

ツリーにはフォルダーだけを載せます。条件に一致したフォルダーと、一致した項目（ファイルを含む）の親・祖先のフォルダーは必ず載せます。それ以外の、一致した項目につながらないフォルダーは載せません。一致したかどうかを区別する印は付けません。階層の位置には、範囲内で最後に観測したパスを使います。

子の並び順はフォルダーが先、その中は名前順で固定し、並べ替えの操作は設けません。ツリーは展開に合わせて読み込み、全件を一度に作ることはしません。

### 一覧

ファイル タブと同じく、ツリーで選んだフォルダーの直下にある検索結果を一覧に表示します。一覧に出すのは、ツリーに載るフォルダーと、条件に一致したファイルです。ページ単位で読み込み、スクロールに合わせて続きを読み込みます。

| 列 | 内容 |
| --- | --- |
| 名前 | 属性のアイコンと名前 |
| サイズ | L での値 |
| 増減 | F から L への増減 |
| 操作 | グラフのボタン、ごみ箱のボタンの順に並べる |

列の見出しをクリックすると、ほかのタブと同じく並べ替わります。

### 操作

ツリーと一覧では、ファイル タブと同じ[ファイル操作](file-actions.md)（開く、パスのコピー、ごみ箱への移動、ダブルクリックでの移動・起動）を使えます。履歴に記録されたパスが今も存在するとは限らない点は、ファイル タブと同じです。

これに加えて、次の操作でグラフのウィンドウを開きます。

- 一覧の各行で、ごみ箱のボタンの左にあるグラフのボタンをクリックする。
- ツリー・一覧の右クリックメニューで「グラフで開く」を選ぶ。

## グラフのウィンドウ

ツリーまたは一覧で選んだ 1 項目について、新しいウィンドウにサイズの推移を表示します。複数のウィンドウを同時に開けます。

- 横軸はスキャンの完了日時で、実際の時間の間隔で並べます。縦軸はサイズです。
- 割り当てサイズと論理サイズを切り替えられます。既定は、画面の「サイズ」と同じ割り当てサイズです。
- 観測できなかったスキャンと、サイズが未解決のスキャンは 0 として描かず、線を途切れさせて印を付けます。
- 点にポインターを合わせると、スキャン日時・サイズ・その時点のパスを表示します。パスは、そのスキャンでの親フォルダーと名前から組み立てるため、移動や名前の変更は反映されます。ただし祖先のフォルダーの名前が変わっていた場合、祖先の部分は検索結果のツリーと同じ（最後に観測した）名前で表示します。

### 描画ライブラリ

描画には [LiveCharts2](https://github.com/beto-rodriguez/LiveCharts2)（`LiveChartsCore.SkiaSharpView.WinUI`、MIT）を使います。ScottPlot と自前の XAML 描画を比較し、次の理由で選びました。

- 枠線のない Fluent に近い見た目で、日付の目盛りが短い。
- 値を null にするだけで線が途切れ、ポインターを合わせたときの表示が組み込まれている。

依存には次の手当てが必要です。

- ライブラリは Windows App SDK の一括パッケージ（`Microsoft.WindowsAppSDK`）に依存します。そのままでは古い版が選ばれ、アプリの WinUI の分割パッケージと衝突してビルドが失敗します。そのため、一括パッケージを、WinUI の分割パッケージと同じ版の組を含む版に固定します。
- 一括パッケージに含まれる AI・ML・Widgets・Runtime のパッケージは、`ExcludeAssets="all"` で除外します。除外しないと onnxruntime や DirectML などが同梱され、配布サイズが約 67 MiB 増えます。除外した場合の増加は約 20 MiB（SkiaSharp、ANGLE、HarfBuzz とライブラリ本体）です。
- Windows App SDK を更新するときは、一括パッケージと除外する各パッケージの版を、WinUI の分割パッケージに合わせて揃えます。
- 採用時は [THIRD-PARTY-NOTICES.md](../THIRD-PARTY-NOTICES.md) とロックファイルを更新します。

縦軸の目盛りは、「13.97 GiB」のような半端な値にならないよう、2 進単位で区切りのよい間隔をアプリ側で決めます。

## 処理とメモリ

条件の評価は DuckDB 側で行い、結果だけを読み込みます。メモリの予算は、保存処理と同じく[その PC で使える量](storage.md#メモリ予算)から決めます。メモリが多い PC では速くなりますが、メモリが少ない PC でも失敗させない方式にします。全世代の全行を .NET 側へ一度に読み込む方式は採りません。

検索中と結果の表示中は、S のスキャンをリースで保護します。履歴データベースの最適化・移動・削除の前には、検索の結果を破棄してリースを手放します（条件の入力は残ります）。グラフのウィンドウは、開くときに時系列を一度だけ読み、その後は結果を破棄しても開いたままです。

### 速度の目安

2 百万ファイル × 30 世代の履歴で、使える量が約 20 GiB のとき、全件が結果になる検索は約 7 秒、条件で絞った検索は 3〜5 秒、1 項目の時系列は約 0.6 秒でした（[計測](plans/search-implementation.md#進捗と計測結果)）。メモリが少ない PC でも失敗しないよう、DuckDB の上限を超える場合は再試行しますが、その分は遅くなります。さらなる高速化は[見送り](plans/repository-migration.md#d-検索の高速化見送り)ました。

## 実装上の制限

- 条件の入力は、空欄を「指定なし」と読みます。サイズと増減は小数でも入力でき、バイト数に丸めます。数値は Windows の地域設定で読みます。拡張子は空白・カンマ・セミコロンで区切り、先頭の点は無視します。
- 結果画面のごみ箱のボタンは、その検索と同じボリュームの、今回の起動で取得した最新のスキャンがあるときだけ表示します。ボリュームの識別（シリアル）をそのスキャンから得て、ファイル タブと同じ確認を行うためです。
- 一覧のサイズに付く「\*」は、一部のサイズが未解決のため確定できない値を含むことを示します。
- グラフの線が途切れた箇所（破線の印）には、その時点で項目が見つからなかった場合と、サイズが未解決だった場合が含まれ、ツールチップは出ません。
- 検索のタブは、履歴データベースがあるときだけ使えます。選択したドライブに履歴がないときは、条件画面に理由を示して検索を無効にします。
