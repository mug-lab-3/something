# 起動時の履歴復元

起動時は、全ドライブの保存済み情報を復元してから、選択中ドライブのファイル表示を生成します。

スプラッシュの外周は、DWMの境界色指定だけでなく、`WS_BORDER` / `WS_DLGFRAME` と拡張枠スタイルを除去して枠なしにします。通常画面への切り替え時には元の枠スタイルを復元します。内部描画のキャプチャーではOS側の枠を検証できないため、`--demo --smoke-test <画像パス> --smoke-startup --preview-dark` では実ウィンドウの外周も含む `<画像パス>.window.png` と枠スタイルの診断を保存し、枠の除去・復元を検証します。`--preview-startup` では確認用にスプラッシュを表示し続けます。いずれもデモ専用です。

起動時は640×240 DIPの横長スプラッシュ（左にアイコン・Something・現在の処理、右にひよこスキャナー）を画面中央に表示します。タイトルバー・枠・操作ボタンを表示せず、読み込みが終わってから通常サイズとタイトルバーに切り替えます。サイズはモニターのDPIに合わせます。通常画面は非表示・操作不可とし、全ドライブの履歴と選択ドライブの初期表示が揃ってからまとめて切り替えます。アニメーションは進行中の1.2秒周期だけを最後まで再生し、システムでアニメーションを無効にしている場合は待ち時間を追加しません。起動中の終了ではアニメーションと読み込みをキャンセルします。履歴読み込みのエラーは通常画面へ切り替えて通知します。

1. 各ドライブの識別情報と履歴を読み、最新の保存済みスキャンを開いてカードへ反映します。この段階では表示条件による集計、ツリー、ファイル一覧、容量分析を読み込みません。まだ確認できていないカードは「履歴を確認中」とし、履歴なしと区別します。
2. 全カードの確認が終わってから選択中ドライブの表示と記録選択を読み込みます。初回起動ではこの表示処理までローディング画面で覆います。DB管理操作後の再読み込みでは、従来どおりカードの操作を表示処理の前に再開します。

ドライブ単位の識別・履歴読み込みが失敗しても残りを続けます。失敗したカードは「履歴を読み込めません」と表示し、未スキャンとは扱いません。エラーも通知します。キャンセルや終了時は処理を打ち切ります。スキャンや実ファイルの変更は行いません。DB最適化後の再読み込みも同じ順序です。

合成履歴の画面検証では、既存のセッションを解放して3台分を復元し、全セッションが開いていてもファイル一覧・容量分析がまだ空であることを確認します。その後に選択中ドライブの表示、履歴選択、他ドライブへの切り替えを検証します。実行例は `--demo --demo-history <専用ディレクトリ> --smoke-test <画像パス>` です。
