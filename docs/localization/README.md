# 表示文言のリソース化

## 現在の段階

日本語の定義を `src/Something.App/Strings/ja-JP/Resources.resw` に用意した。
WinUI / MRT Core の標準的な XML リソース形式で、アプリの既定言語は `ja-JP`。
この段階では画面・C# のハードコードをまだ置き換えていない。表示動作は従来と同じ。
次段階で XAML の `x:Uid` と C# のリソース取得に接続する。
現時点のキーは文字列の識別子であり、XAML のプロパティへ自動適用するキーではない。
接続時にプロパティ用キーが必要な場合は、その対応も一覧に反映する。

文言と出典は [日本語リソース一覧](ja-JP-inventory.md) を参照。
各 `<data>` の `comment` に出典・メンバー名・書式引数の式を記載している。
英語の診断メッセージには日本語定義を用意し、元の英語をコメントに残した。
同じ文字列と引数数の組を共有している。翻訳時に意味・文脈が異なることが判明したら
キーを分割する。キー名の番号は表示順ではなく識別子として維持する。

## 対象

- タブ、ボタン、列ヘッダー、設定、ダイアログ、トースト、ツールチップ、読み上げ用名称。
- ドライブカード、比較期間、日付・数値を含む表示書式、スキャン・集計・保存の進捗。
- アニメーションの `!`、`ピーッ ♪`、`じゃっ！`。
- アニメーションプレビューの操作・状態表示と、トーストプレビューの埋め込み XAML。
- デモ画面の表示文言。容量単位や記号は、日本語でも同じ表記で定義する。
- NTFS / Windows / 統計 / 永続化 / アプリケーション層の診断文字列。
  実際に表示される可能性のある失敗理由を落とさないよう、内部検証用例外も保守的に含めた。

下位層を UI リソースに依存させる設計にはしない。
診断の接続は、将来、構造化した診断コードと引数を UI 境界で翻訳する方法を検討する。
英語メッセージの文字列比較で診断を翻訳しない。

## 除外と実行時データ

[source-inventory.json](source-inventory.json) に、抽出した各文字列のリソースキー、
または除外理由を記録している。除外には以下を含む。

- SQL、スキーマ、マイグレーション、接続文字列、内部 ID、コマンドライン引数。
- ネイティブ API 名、正規表現、書式指定子、フォントのアイコングリフ、アニメーションのプロパティ名。
- Windows の保護対象パスの実名、パスの区切り、空文字、検証用アサーション。
- DuckDB のメモリ不足を検出するために照合する固定トークン。翻訳すると検出が壊れる。

ファイル名・パス・ボリューム名・利用者が保存したデータ、OS / .NET / DuckDB が
実行時に生成するメッセージは、この定義ファイルの静的文言ではない。
外部エラーをそのまま表示する場合、日本語 resw があっても日本語になるとは限らない。
単位・記号の有無と、翻訳不要の実データを区別する。

## 書式と翻訳時の注意

補間文字列は `{0}`、`{1:N0}` などの複合書式にしている。
引数全体の並べ替えは可能。引数の欠落・追加や括弧の破損はチェックで検出する。
接頭辞や区切りを含む文字列は `xml:space="preserve"` で空白を保持する。
連結されている既存文言も出典ごとに残しているが、参照の置換時には文章全体の
リソースへまとめる。言語によって語順が変わるため、単語の連結を翻訳方式にしない。
日付書式も一覧に含めた。将来は言語・カルチャーごとの書式を選び、
カレンダーの設定と整合させる。現段階では言語選択や動的な言語切り替えは追加していない。

## 確認方法

リポジトリのルートで実行する。

```powershell
dotnet run --project tools/Something.LocalizationAudit -- check .
```

このツールは固定 SDK に含まれる Roslyn を使用し、追加の外部ツールを必要としない。
`src` 以下の C# 文字列・補間文字列と XAML の表示プロパティ・テキストを抽出する。
埋め込み `XamlReader.Load` の静的 XAML も対象。
新しい独自コントロールの文字列プロパティを追加する場合は、抽出対象にも追加する。
バインディングから来る文字列は、その C# 側の定義を確認する。

未分類・削除済みの出典、リソースの欠落・空値・重複キー・未使用定義、
書式引数の不一致を確認する。出典の指紋はファイル・メンバー・文字列・引数式から作り、
単なる行番号の移動では失敗させない。行番号は初回棚卸し時の位置である。
チェック成功は抽出・対応の整合性を示すもので、翻訳の意味や UI の表示品質を保証しない。

再調査には次を使う。結果は追跡対象外の `artifacts/localization-extracted.json` に出力される。

```powershell
dotnet run --project tools/Something.LocalizationAudit -- extract .
```

文言変更時は出典を人が確認し、resw・機械用一覧・読みやすい一覧を更新してから
チェックを実行する。除外理由が必要な項目を自動的に「翻訳不要」と決めつけない。
監査ツールは新しい CI ワークフローやバックグラウンド処理を追加しない。

標準方式の参照: [Microsoft: Localize strings in your UI](https://learn.microsoft.com/en-us/windows/apps/windows-app-sdk/mrtcore/localize-strings)。
