# スキャン履歴

2026-10-14。WinUIアプリの成功したドライブ全体スキャンを自動保存し、保存済みの日時を選んで閲覧できる。
ファイル・フォルダの肥大化を比較するための記録基盤。差分計算・増加ランキングはまだ実装しない。

## 保存と閲覧

- 保存先は `%LOCALAPPDATA%\Something\History`。`catalog.sqlite3` はEF Coreで管理する小さな索引、
  `snapshots\<scan-id>.sqlite3` は1スキャンのSQLite DB。新しいEFマイグレーションをチェックインする。
- 各スキャンでファイル参照のシーケンス番号、全可視名／DOS別名、名前付きストリーム、論理／割り当て容量、
  フォルダ集計、未解決状態を丸ごと保持する。保持履歴の記録内容を減らさない。
- 作業用DBからSQLiteのバックアップAPIで新しい一時名へ書き出し、フラッシュ後に最終名へ移動する。
  その後に索引をトランザクションで公開する。既存ファイルを上書きしない。
  キャンセル・失敗したスキャンは公開せず、古い履歴を先に削除しない。
- メモリDBでは従来の破棄用書き出しを履歴保存に置き換え、同じ結果を二重に書き出さない。
  ファイルDBでもバックアップAPIを使い、未コミットの状態を単純コピーしない。
- 起動時に各ドライブの最新履歴を読み込み、一覧上部の日時セレクターで過去の結果を選ぶ。
  履歴DBは読み取り専用で開き、スキャンし直さずに一覧／ツリー／ランキングを閲覧する。
  最新の作業用DBは終了時に破棄するが、履歴DBは保持する。
- ボリュームGUIDとNTFSシリアル番号を合わせて区別する。ドライブ文字だけを永続キーにしない。
  GUIDの取得はMicrosoftの [GetVolumeNameForVolumeMountPointW](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-getvolumenameforvolumemountpointw) を使う。
  起動時の識別確認は読み取り専用のボリューム情報取得だけで、MFT走査は行わない。
- 通常の `--demo` は履歴を保存しない。検証用の `--demo-history <専用ディレクトリ>` を明示した場合だけ、
  合成観測をそのディレクトリへ保存する。実ドライブ／実ファイルは取得しない。
  LiveInspect CLIは従来どおり診断用の一時DBを使い、自動履歴保存の対象にしない。

## 保持ルール

基準時刻は世代の終了UTC。日付とUTCオフセットは保存時のPCローカル時間で記録し、
後からタイムゾーンを変更しても既存履歴を別の日へ振り分け直さない。

1. 現在時刻から24時間未満の完了記録はすべて保持する。
2. それ以外は、ボリュームごと・記録時のローカル日付ごとの最後の1回を保持する。
3. 同じ日の最終記録がまだ24時間以内なら、それより古い当日の記録を残す必要はない。
4. 24時間ちょうどは整理対象。同じ終了UTCの記録はスキャンIDで決定的に選ぶ。
5. 起動時、保存成功後、アプリ稼働中は1分ごとに整理する。アプリ停止中はファイルを整理せず、次の起動時に追いつく。

例: 14日12時には13日12時より後の記録をすべて残す。13日午前の古い記録は削減できる。
15日になって13日の記録がすべて24時間以上経過したら、13日の最終記録だけが残る。
履歴の最大日数は今回設定しない。

整理は最初に索引で対象を非公開にし、その後でSomethingが所有するスキャンID名のファイルを削除する。
閲覧中の履歴は読み取りハンドルを閉じるまで削除を延期する。他のアプリインスタンスがファイルを使用中などで
物理削除に失敗した場合も、記録を再公開せず次の整理で再試行する。
新しい履歴の公開後に整理が失敗しても、新しい履歴を失敗扱いで取り消さない。

## 制限と検証

- 記録はライブMFT走査の楽観的な観測。スキャンの全期間で同じ時点のディスク状態であったとは保証しない。
  容量未解決や名前の不確実性を維持し、将来の履歴比較でも未解決をゼロ・削除と解釈しない。
- Epochはスキャン単位。USNジャーナルの連続性は未検証で、MFT参照再利用やシーケンス番号の周回を
  またぐ同一ファイル判定を、この履歴保存だけで保証しない。
- 日次に絞ってもフルDBが残るので、保存容量は日数・ファイル数に比例する。DuckDB比較は保留課題のまま。
- ファイル移動と索引のコミットは別の操作。プロセスがその間で強制終了すると、未公開のファイルが残る場合がある。
  索引にないファイルを履歴として表示したり、別プロセスの保存中ファイルを推測で削除したりしない。
- 現行スキーマの読み取り専用スナップショットを検証し、異なる未対応スキーマや索引とID／時刻が違うDBは拒否する。
- 純粋な保持ルール、24時間境界、タイムゾーン変更、保存／再読込、可視名／DOS名／名前付きストリーム／未解決の維持、
  読み取り専用、保存先衝突、キャンセル、不完全スキャン、並行保存、閲覧中の削除延期をテストする。
  デモUIでも履歴選択と最新結果への復帰を検証する。実ドライブ全件を用いた履歴保存・再起動・経過後の整理は実機確認が必要。
