# 複数起動の防止

起動時にWindows App SDKの`AppInstance.FindOrRegisterForKey`で所有者を決めます。キーにはユーザーSIDとWindowsセッションを含め、通常起動・合成データの`--demo`・単体アニメーション確認の`--animation-preview`を区別します。単体確認は通常画面や履歴DBを生成せず、通常版・デモと同時に開けます。追加パッケージ・設定ファイル・定期監視は不要です。

2回目以降はXAML・メインウィンドウ・履歴DBを初期化せず、既存インスタンスへ起動を転送して終了します。受信側はUIスレッドに処理を送り、最小化されていれば復元してウィンドウをアクティブにします。最前面化はWindowsのフォアグラウンド権限制御に従います。初回の画面作成前に転送が届いた場合は、その後の通常起動で画面が表示されます。

カスタムエントリーポイントを使い、最初のインスタンスはSTAのままWinUIを開始します。転送する側だけ非同期で完了を待つため、STAを同期的に塞ぎません。転送には10秒の待機上限を設け、失敗・タイムアウト時も2つ目のDB接続を作りません。キーは非同期の終了処理とUIメッセージループが完了するまで保持します。終了後は再起動できます。

2026-10-18に、非昇格の合成データ専用ビルドで、2プロセス起動時の転送側の正常終了、既存プロセスの維持、最小化からの復元、正常終了後の再起動を確認しました。実ユーザーのDBやスキャンは使っていません。

実装の基準はMicrosoftの[WinUIの複数インスタンス管理](https://learn.microsoft.com/en-us/windows/apps/develop/launch/multi-instance-apps)です。SDKのアプリ識別の範囲で起動を管理し、他のWindowsユーザーや別セッションの画面は操作しません。
