# 履歴の絞り込み検索の実装計画

[履歴の絞り込み検索](../search.md)を実装するための計画です。仕様は `search.md` を正とし、この文書には作業の順序、設計上の判断、検証の方法を記録します。作業が進んだら、各段階の状態と計測結果を更新します。

## 前提となる事実

| 事実 | 影響 |
| --- | --- |
| 名前は UTF-16LE のバイト列として BLOB に保存している（[`StorageEncoding.Name`](../../src/Something.Storage/StorageModels.cs)）。DuckDB の VARCHAR は不正な Unicode を保持できないため、意図した形式 | 名前・拡張子・正規表現の照合は SQL では行わず、.NET 側で行う |
| 世代ごとの一覧（名前・親・属性・サイズ）は、ビュー `browser`（[`SharedHistoryViews`](../../src/Something.Storage/SharedHistoryViews.cs)）で引ける。ファイルは `StreamAllocated`/`StreamLogical`、フォルダーは `EntrySubtreeAllocated`/`EntrySubtreeLogical` で、どちらも名前別容量 | 世代をまたぐ数値の集計は、このビューを S の世代に絞って行う |
| MSI は publish の出力をまとめて取り込む（[`Package.wxs`](../../installer/Package.wxs)） | LiveCharts2 の DLL を追加しても、インストーラーの定義は変えなくてよい |
| LiveCharts2 は Windows App SDK の一括パッケージに依存する | 一括パッケージの版の固定と、不要なパッケージの除外が必要（[描画ライブラリ](../search.md#描画ライブラリ)） |

## 設計上の判断

- **評価の分担**：数値の条件（サイズ・増減・振れ幅・存在）は DuckDB 側で集計して候補を絞る。名前・パス・属性は、候補を順に読みながら .NET 側で照合する。
- **SQL の書き方**：まず EF Core・LINQ で実装して計測する。単調増加・単調減少のように LINQ で表現しにくい処理も含め、手書きの SQL は、計測でボトルネックと確認した処理に限り、根拠をこの文書に残して保存層の中で使う。
- **正規表現**：.NET の書式とし、`RegexOptions.NonBacktracking` を使って、入力によって処理時間が爆発しないようにする。大文字と小文字は区別しない。
- **結果の保持**：一致した項目は、メモリ上のコンパクトな配列に保持する。ディスクに一時表は書かない。ツリーと一覧は、この配列から親ごとにページ単位で引く。
- **メモリ**：予算はその PC で使える量から決め、`ScanMemoryBudget` で予約する。全世代の全行を .NET 側へ一度に読み込まない。メモリの少ない PC でも失敗させない。
- **スキーマ**：変更しない。名前の照合がボトルネックだと計測で確認できた場合に限り、検索用の列の追加を改めて検討する。

| 対象 | 内容 |

| 保存層 | 合成した複数世代の履歴で、出現・消失、未解決、属性不明、F が 0 のときの増減率、S が 1 件、名前の変更・移動、ハードリンク、DOS 別名を照合しないこと、単調性、検索中の退役、キャンセル |
