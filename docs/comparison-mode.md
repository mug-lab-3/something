# サイズ表示と履歴比較

比較後のディスク上の割り当て容量から、比較前の容量を引く。正は増加、負は減少、既知のゼロ差は `±0 B`。フォルダ容量はサブフォルダ込み。通常表示と同じく可視名ごとに無名DATAを計上し、ハードリンクの各名前もそれぞれ比較する。ランキングの親子行は容量が重複するので、行の差分を足してドライブの増減としない。

## 期間と記録の選択

通常／差分のモード切り替えを設けず、画面上部の「表示する記録」と「比較」で操作する。表示する記録の最新行には「最新」と付ける。「比較：なし」でサイズのみ、期間または任意の比較元を選ぶと同じ画面に増減を加える。任意指定も比較後は「表示する記録」を使い、比較元だけを追加選択する。

| 選択 | 要求する開始境界 |
| --- | --- |
| 24時間・7日間・30日間・365日間 | 表示中のスキャン完了時刻から指定した経過時間を引く |
| 今日 | 表示中の記録のローカル日付の0時 |
| 今週 | 表示中の記録が属する週の月曜日の0時 |
| 今月・今年 | 表示中の記録が属する月・年の開始時刻 |
| 任意のスキャン | 表示中の記録に対する比較元を直接選択 |

自動期間の比較後は表示中の記録で固定する。現在時刻や最新記録へ自動で切り替えず、選択した記録より後のデータを使わない。同じ完了時刻が複数ある場合は履歴と同じID順で選択記録より後を除外する。比較前は開始境界以前の最後の記録を優先する。なければ期間内の最古を使い、「履歴がある範囲のみ」と明記する。2つの異なる記録を選べなければ履歴不足で、1記録だけで差分0を作らない。任意の比較元は不足する選択を自動で別記録に置き換えない。暦の区切りはPCのローカルタイムゾーンで計算する。

期間選択のすぐ下に、実際に選んだ「比較前のスキャン日時 → 比較後のスキャン日時」を常に表示する。プリセットの要求期間も併記し、履歴がない側は「記録なし」と表示する。夏時間で0時が存在しない場合は最初の有効な時刻、重複する場合は早い方の時刻を境界にする。任意選択では同じボリューム・時刻の順序を検証する。

直近24時間以前は既存の保持方針に従い1日最後の記録だけ残る。任意指定は残っている記録から選び、削除済みの時刻を復元・補間しない。比較用にスキャンや履歴のコピーを追加保存しない。履歴の選択は比較中も利用でき、選択した時点を基準として比較を更新する。

## 一覧・ツリー・ランキング

一覧の「サイズ」は常に表示中の記録のディスク上の容量。比較時だけ「増減」を追加し、比較前の容量はツールチップで確認する。比較前だけに存在する項目のサイズは「—」として、現在も存在するとは扱わない。比較時は両記録の項目を合わせ、増減の絶対値が大きい項目を先に置き、スクロール時に250件ずつ画面に追加する。同じフォルダ内で名前が変わった場合、世代を含むファイル参照が同じで対応が一意なら対にする。複数ハードリンクで対応が曖昧なら別行に残す。名前変更前の名前はツールチップで確認できる。

ツリーは名前に数値を付けず、展開矢印と名前の間に固定幅の増減アイコンを置く。増加はオレンジの上向き矢印、減少は緑の下向き矢印、比較不能・片側の記録なしはグレーの疑問符。変化なしは空欄で、比較しないときは領域自体を使わない。フォルダアイコンは追加しない。名前・サイズ・比較前・増減の数値はツールチップ、増減方向の説明はアクセシビリティ名で確認できる。比較前だけのフォルダも、その記録から閲覧できる。

ランキングは単一のタブに統合し、サイズ順を常に利用できる。比較中だけ増加順・減少順・絶対値順を有効にし、これらは数値比較できるフォルダを対象とする。サイズ列を残して増減列を加え、深さ・最下位フォルダの条件を維持する。

片方にしか記録がない項目は「前の記録なし」「後の記録なし」。新規作成・削除の確定や0との引き算は行わない。容量未解決・名前集合未確定・帰属不明などで比較できない容量は数値差分にしない。フォルダの移動・名前変更はボリュームとMFT番号・世代番号で対応させる。フォルダ内のファイル移動は、移動元・先の一覧では片側の記録として表示する。世代番号が変わったMFT番号は別物。世代の周回などを含め、長期間の連続した同一性を保証するものではない。

## 実装と検証

既存DuckDB履歴と型付きLINQモデルを利用し、DBスキーマの追加・移行は不要。`ComparisonSelection` が期間・端点を決め、`ScanHistoryArchive.ReadFolderChanges` がフォルダ差分、`EntryChanges` が可視項目の対応と符号付き容量差を計算する。UIは読み取りをバックグラウンドで行い、比較選択の変更時は古い要求をキャンセルして世代を検証する。履歴の読み取り所有権は閲覧終了時に解放する。

フォルダ内の差分順を決めるには、そのフォルダ直下の両記録を先に読み取る。比較のたびに全ファイルをメモリへ展開する方式ではないが、非常に多くの直下項目を持つフォルダでは待ち時間・メモリ使用が増える。直近に比較した1フォルダだけ結果を再利用する。巨大な実機履歴での応答時間は別途確認が必要。

期間境界（夏時間を含む）、保持済み端点、履歴不足、異なるボリューム、選択順序、世代再利用、ハードリンク、名前変更、未解決、符号と容量の上限、キャンセルを自動テストで検証する。既存の合成データ用画面テストに `--smoke-comparison` を追加し、2記録の比較・子フォルダ移動・履歴不足・通常表示への復帰・古い要求のキャンセルを検証する。実ディスクや本物の履歴はテストで変更しない。

ドライブ・表示する記録・比較条件の切り替え中は、条件欄とツリー・一覧・ランキングをまとめて読み込み表示で覆い、古い結果への操作を止める。各部分の読み込みとレイアウトが揃ってから一括で表示する。重なった読み込みやキャンセルでも、途中の処理完了だけで表示を再開しない。ドライブカードは引き続き選択できる。

待機表示は[DBの巣とレコードひよこのアニメーション](loading-animation.md)を使い、処理完了後は再生中の1周が終わってから結果へ切り替える。

ツリーは横スクロールできる。深い階層の選択・展開や幅の変更時には、対象の名前とその左の操作領域が見えるよう横位置を調整する。ルートを選び直すと左端へ戻す。長い名前では末尾ではなく先頭を優先して表示し、手動の横スクロールも妨げない。名前の列は階層の字下げで縮めず文字幅を確保する。未表示の行は標準の仮想化で表示してから調整し、古い選択や別ドライブのツリーから遅れて届いた要求では位置を戻さない。追加のDB読み取りは行わない。
