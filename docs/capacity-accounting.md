# 容量集計

## サイズの意味

画面の「サイズ」は、DATA の割り当て容量です。フォルダーの値は、サブフォルダーを含めた配下の合計です。論理サイズはファイルの長さ、割り当てサイズは DATA のために確保された容量で、圧縮・スパース・常駐データによって異なります。

常駐 DATA の追加のクラスタ割り当ては 0 ですが、MFT レコードを占有していないという意味ではありません。索引・MFT・ログなどを含むボリュームの使用済み容量と、ファイルの DATA の合計が一致するとは限りません。

集計した容量は `UInt128`、符号付きの増減は `BigInteger` で扱います。未解決のサイズは nullable の値と品質情報で区別し、0 バイトとはしません。

## 2 つの集計ポリシー

| 指標 | 対象・ハードリンクの数え方 | 用途 |
| --- | --- | --- |
| 名前別容量 | 無名 DATA を各可視名に計上。DOS 別名は別ファイルとして加算しない | ファイル・容量分析・画面の履歴比較 |
| 重複排除した DATA 容量 | 名前付きストリームを含む各ファイルの DATA を一度だけ帰属 | 全体の保存則と容量帰属の診断 |

NTFS のハードリンクに「元」と「コピー」の区別はありません。たとえば同じ 10 MiB のファイルが `A\x` と `B\y` にある場合、名前別表示は A と B にそれぞれ 10 MiB を表示します。リンクを小さな別ファイルとして扱うことはしません。リンクを 1 つ消しても、ほかの名前が残っていれば、通常はデータの容量は解放されません。

重複排除のポリシーでは、同じフォルダーにある名前はそのフォルダーへ一度だけ、複数フォルダーにまたがる場合は最も近い共通祖先の共有容量へ一度だけ帰属します。A と B がドライブ直下なら、その共有容量はドライブのルートに属します。共有容量と各リンク名の表示は別の指標です。

名前集合は列挙した FILE_NAME を基準にします。ヘッダーのリンク数と列挙できた名前の数が一致しないだけで、列挙できたファイルを集計から外すことはしません。不一致は診断情報として残し、DOS 名前空間・親参照・重複・名前集合の欠けの検証は続けます。

## 階層と所属不明

フォルダーの識別は MFT 番号とシーケンスの組です。親参照の存在、シーケンス、ディレクトリ種別、循環、ルート到達を検査します。親を解決できない項目を、都合のよい既知のフォルダーへ付け替えることはしません。

重複排除した既知 DATA は次の区分へ分けます。

1. ルート配下へ帰属できた通常容量。
2. NTFS メタデータとして識別した既知 DATA。
3. 親・名前・階層等の問題により帰属できない既知 DATA。

既知の入力の合計と、この区分の合計が一致することを検査します。`conservation-match` はこの保存則の検査であり、全ファイルの容量を独立に証明するものでも、所属不明がないことを保証するものでもありません。未解決の管理ファイルは通常フォルダーの未解決と分けます。

## 表示対象の属性

Hidden / System は本体の STANDARD_INFORMATION から判定し、両方が付いている場合もそのまま保持します。「通常」とは両方のビットがオフという意味で、`Normal` ビットは必須にしません。不明な属性を通常として補うことはしません。

表示設定はツリー、一覧、容量分析、比較の両端に適用します。除外したフォルダーの配下も除外し、属性が不明な項目は残します。ハードリンクは、対象に残った名前について数えます。スキャンと保存は設定にかかわらず全件が対象で、設定を変えても DB の内容を削ったり書き換えたりはしません。

## 比較の注意

サイズの増減は、2 つの観測の差です。名前別容量の変化には、内容の増減だけでなく、移動・リンク追加・属性による対象変更も影響します。親と子のフォルダーの値は重複するため、容量分析の全行を合計してドライブ容量にしません。

エクスプローラーの表示と比べる場合も、観測した時刻・権限・再解析ポイント・ストリーム・ハードリンクの条件をそろえて確認します。ドライブの使用済み容量と比べるときは、名前別容量ではなく、重複排除した DATA と管理領域の差を使います。
