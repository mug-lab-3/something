# 容量集計

## サイズの意味

画面の「サイズ」は DATA の割り当て容量を基準とします。フォルダはサブフォルダを含む配下の値です。論理サイズはファイルの長さ、割り当てサイズは DATA のために確保された容量で、圧縮・スパース・常駐データによって異なります。

常駐 DATA の追加クラスタ割り当ては 0 ですが、MFT レコードの占有がないという意味ではありません。索引・MFT・ログ等を含むボリューム使用済み容量と、ファイル DATA の合計は一致を要求しません。

集計容量は `UInt128`、符号付きの増減は `BigInteger` を使用します。未解決のサイズは nullable 値と品質情報で区別し、0 バイトにしません。

## 二つの集計ポリシー

| 指標 | 対象・ハードリンクの数え方 | 用途 |
| --- | --- | --- |
| 名前別容量 | 無名 DATA を各可視名に計上。DOS 別名は別ファイルとして加算しない | ファイル・容量分析・画面の履歴比較 |
| 重複排除した DATA 容量 | 名前付きストリームを含む各ファイルの DATA を一度だけ帰属 | 全体の保存則と容量帰属の診断 |

NTFS のハードリンクに「元」と「コピー」の区別はありません。たとえば同じ 10 MiB のファイルが `A\x` と `B\y` にある場合、名前別表示は A と B にそれぞれ 10 MiB を表示します。リンクの実体を小さな別ファイルとして扱う方式ではありません。リンクを一つ消しても、他の名前が残ればデータ容量は通常解放されません。

重複排除のポリシーでは、同じフォルダにある名前はそのフォルダへ一度だけ、複数フォルダにまたがる場合は最も近い共通祖先の共有容量へ一度だけ帰属します。A と B がドライブ直下なら、その共有容量はドライブのルートに属します。共有容量と各リンク名の表示は別の指標です。

名前集合は列挙した FILE_NAME を基準にします。ヘッダーのリンク数と列挙名数の不一致だけで、列挙できた全ファイルを集計から除外しません。不一致は診断として保持し、DOS 名前空間・親参照・重複・名前集合の不完全さの検証は続けます。

## 階層と所属不明

フォルダの識別は MFT 番号とシーケンスの組です。親参照の存在、シーケンス、ディレクトリ種別、循環、ルート到達を検査します。親を解決できない項目を、都合のよい既知フォルダへ付け替えません。

重複排除した既知 DATA は次の区分へ分けます。

1. ルート配下へ帰属できた通常容量。
2. NTFS メタデータとして識別した既知 DATA。
3. 親・名前・階層等の問題により帰属できない既知 DATA。

既知の入力合計とこの区分の合計が一致することを検査します。`conservation-match` はこの保存則の検査であり、全ファイルの容量の独立証明や、所属不明がないことの保証ではありません。未解決の管理ファイルは通常フォルダの未解決と分けます。

## 表示対象の属性

Hidden / System は本体の STANDARD_INFORMATION から判定し、両方が付く場合も保持します。通常属性とは両ビットがオフの意味で、`Normal` ビットを必須にしません。不明な属性を通常として補完しません。

表示設定はツリー、一覧、容量分析、比較の両端に適用します。除外フォルダの配下も除外し、属性不明は残します。ハードリンクは対象に残った名前に対して計上します。スキャンと保存は設定にかかわらず全件を対象とし、設定変更で DB を削ったり書き換えたりしません。

## 比較の注意

サイズ増減は二つの観測の差です。名前別容量の変化には、内容の増減だけでなく、移動・リンク追加・属性による対象変更も影響します。親と子のフォルダの値は重複するため、容量分析の全行を合計してドライブ容量にしません。

Explorer と比較する場合も、観測時刻・権限・再解析ポイント・ストリーム・ハードリンクの条件をそろえて確認します。ドライブの使用済み容量との比較には、名前別容量ではなく重複排除した DATA と管理領域の違いを使います。
