# スキャン履歴の管理

ドライブカードの下にある「ファイル／DB管理」タブで、フォルダ・ファイルの容量表示と履歴管理を切り替えます。対象ドライブは上部カードで共通に選びます。DB管理内に別のドライブ選択や「すべてのドライブ」は設けません。表示中のドライブを切り替えると、履歴一覧も切り替わります。

手動更新ボタンと定期監視は設けません。タブ・ドライブの切り替え、スキャンの保存完了、履歴削除後に一覧を読み直します。別ドライブの保存時も、共有DB内の保持ルールによって表示中ドライブの履歴が整理される場合があるため、表示中の一覧を更新します。

DB管理タブには保存済みスキャンの完了日時・記録数を表示し、その上に日時範囲、期間ボタン、選択件数、削除ボタンを配置します。日時は一つの枠内で「–」につなぎ、未指定の端は「最初の記録」「最新の記録」と表示します。各端を押して日付・時刻を編集し、「×」で入力範囲をクリアできます。範囲の反映は右側の枠なしチェックアイコンから行います。通常の文字色を使い、ツールチップとアクセシビリティ名は「この範囲で選択」です。開始・終了のラベルは画面上には設けず、ツールチップとアクセシビリティ名で補います。削除対象は常に一覧でチェックした履歴です。「削除方法」の切り替えはありません。

- 日時の編集だけではチェックを変えません。「✓（この範囲で選択）」を押したときに、入力した範囲に該当する履歴へチェックを付け直します。
- 開始日時が未指定なら最初から、終了日時が未指定なら最新までを選びます。両方未指定で「✓（この範囲で選択）」を押すと全履歴を選択します。入力のクリアだけではチェックを変えません。
- 「1か月前以前」「3か月前以前」「半年前以前」「1年前以前」の個別ボタンは、操作時点から暦月でさかのぼった日時を終了日時へ設定し、開始日時を空欄にします。これも入力の変更だけで、チェックへの反映には「✓（この範囲で選択）」を押します。
- 範囲を反映した後も、一覧でチェックを個別に追加・解除できます。日時範囲は一覧のフィルターではなく、チェックを付ける補助です。
- 一覧ヘッダーのチェックボックスから全選択・解除します。未選択は空、全選択はチェック、一部選択は横線で表示します。未選択・一部選択の状態で押すと全選択、全選択の状態で押すと解除します。空の一覧や処理中は操作できません。更新時は同じドライブ内で残っている選択IDだけを保持し、新しく保存された記録を自動追加しません。ドライブ切り替え時は選択と入力範囲をリセットします。

表示と入力にはPCの現在のタイムゾーンを使用し、入力時刻の秒は00です。日時の表示形式は現在のカルチャに合わせます。区間の両端と「以前」の境界を含みます。開始が終了より後の範囲や、夏時間の切り替えで存在しない・重複する日時は反映時に拒否し、現在のチェックを維持します。

「履歴を削除」で選択IDを固定し、確認ダイアログで対象件数と実際の最古・最新の完了日時を確認してから「削除する」で実行します。ダイアログには初期状態オフの「削除後にDBを最適化する」を設けます。キャンセルでは削除しません。確認後に保存された新しいスキャンは対象に加えません。実行中はドライブとタブの切り替えを止め、取り違えを防ぎます。

削除するのはDB内のスキャン履歴です。ドライブ上の実ファイルには触れません。まず対象履歴をトランザクションで非公開にし、画面の参照を解放してから関連データを削除します。現在表示している履歴を削除した場合は、そのドライブの残る最新履歴へ切り替え、残る履歴がなければ未スキャン表示にします。比較元を削除した場合は比較を解除します。

別のウィンドウやプロセスが読み取り中の履歴は、読み取りを維持したまま非公開にし、参照解放後の整理まで物理削除を延期します。整理は次の管理操作や履歴保存時にも実行します。他のスキャンが参照している共有データは残します。削除済みデータの領域はDuckDB内で再利用され、DBファイルの容量が直ちに縮むとは限りません。

一覧と削除対象の確定・非公開化はEF Core/LINQと型付きモデルで実装し、既存の世代削除と共有データ回収を再利用しています。スキーマの変更はありません。保持規則は直近7日未満の全記録と、7日以上前の各日の最終記録です。新しいスキャンの保存成功後にだけ整理し、起動時や定期的なバックグラウンド整理は行いません。

検証は日時境界・夏時間の単体テスト、合成DuckDB履歴の削除・共有データ保持・独立した読み取りリース・複数ドライブ・キャンセルの統合テストを使います。UIの `--demo --demo-history <専用の空ディレクトリ> --smoke-test <画像パス> --smoke-history-management` は合成履歴だけでタブ、プリセット、区間によるチェック、個別のチェック解除、確認の取り消し、選択削除、空になったドライブ、ドライブ切り替えとファイル表示への復帰を検証します。

記録数は、そのスキャンが保存したMFT観測レコード数です。未解決・拡張レコードを含み、ファイル名・ストリームなど内部テーブルの行数を合算しません。共有データも各スキャンから見た論理件数として数えます。DBの実バイト数や削除で回収される量を表す値ではありません。削除後の物理容量の回収案は [履歴DBの最適化](history-compaction.md) を参照してください。

DB管理タブの「DBを最適化」から、削除を伴わずに共有DB全体を詰め直すこともできます。削除だけの場合は一度のチェックポイントにとどめ、全体の再作成は明示的に選んだときだけ行います。動作と復旧手順は [DBの削除と最適化](history-compaction.md) を参照してください。

DB最適化は上段の日時範囲の右側、選択件数と履歴削除は一覧見出しの右側に配置します。どちらも背景・枠線なしで、最適化は控えめなグレー、削除は赤色です。成功通知は右下に重ねて表示し、6秒後に自動で閉じます。選択操作では消さず、失敗・警告は手動で閉じるまで残します。通知の表示中だけタイマーを使い、履歴の監視や定期更新は行いません。

削除・最適化を確定した後は、処理全体（DB整理、参照の更新、最終的な履歴一覧の再読み込みを含む）を一つのひよこアニメーションで覆います。途中でスピナーへ切り替えず、完了後もアニメーションの区切りまで待って結果と通知を表示します。削除確認をキャンセルした場合はアニメーションを開始しません。
