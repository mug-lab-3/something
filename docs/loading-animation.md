# 読み込みアニメーション

DBを巣に見立て、レコードを表す赤紫のひよこが顔を出して手前へ跳ね、虫眼鏡で確認されて右へ歩いて退場する。次の周回では新しいひよこが巣から出てくる。胸は格子の表ではなく羽毛模様にし、背後の積層したDB円柱で記録との関係を示す。

`RecordLoadingAnimation` のXAML図形とStoryboardで描画する。動画・GIF・画像生成サービス・追加パッケージは実行時に必要ない。ライト／ダークテーマで共通の赤紫とラベンダーを使う。

## 再生と表示の切り替え

| 操作 | 待機表示 |
| --- | --- |
| ドライブ・表示する記録・比較条件の切り替え、初回結果の表示 | 直ちにひよこを表示し、結果をまとめて切り替える |
| ツリーの展開・子フォルダーの追加読み込み | 300ms未満なら表示なし。それ以上は対象行に小さなスピナー。同じ親への重複読み込みは抑止する |
| フォルダー移動、一覧の更新 | 対象の一覧領域だけ操作を止め、300msを超えた場合だけ薄く覆ってひよこを表示。パス・件数・内容は一緒に更新する |
| ランキングの条件変更 | ランキング領域だけで同様にひよこを遅延表示する |
| スキャン | 既存の段階・進捗表示を継続する |

ツリー行のスピナーは完了時に即座に消す。一覧・ランキングのひよこは、再生を始めた場合だけ現在の1周を完走する。300ms未満の操作ではひよこを再生せず、周回待ちも設けない。速い操作の完了後にタイマーで表示が出ないようにし、重なった要求の古い完了で新しい要求の待機表示を消さない。他のツリー行やタブは引き続き操作できる。ドライブなどの全体切り替えでひよこを表示している間は、その内側で局所アニメーションを重複して始めない。

- 1周は1.2秒。顔を出す→跳ぶ→虫眼鏡の前で首をかしげる→足を交互に動かしながら右へ歩いて退場する。巣へは戻らない。描画範囲の外へ出てから姿勢と位置をリセットし、次のレコードとして再登場する。
- 読み込み中は繰り返す。処理完了後は次の周回を始めず、現在の周回の完了イベントで結果を一括表示する。即時完了でも開始した1周は再生する。
- 重なった読み込みは同じ再生を共有する。最後の処理が完了するまで結果を覆い、新しいドライブ選択などが入れば再生を継続する。
- 通常の処理完了・キャンセル・エラーは同じ周回境界で表示を戻す。ウィンドウ終了時はすぐ停止し、待機中の非同期処理を解放する。
- Windowsのアニメーション効果が無効なら、巣の横にいるひよこと虫眼鏡を静止表示し、周回待ちは設けない。

## プレビュー

Releaseビルド後、PowerShellから次を実行する。デモ専用の待機画面でループを確認でき、実ディスクの読み取りや履歴保存はしない。通常版と同じ管理者確認が出る。

```powershell
Start-Process .\src\Something.App\bin\Release\net10.0-windows10.0.26100.0\win-x64\Something.App.exe -ArgumentList '--demo', '--preview-loading'
```

既存の合成データ用 `--smoke-test <画像パス> --smoke-comparison` は、即時完了時の1周完走、入れ子・重複・キャンセル、連続ドライブ切り替えを検証する。追加の `--smoke-loading` で読み込み中の画面を撮影する。

## 検討した案

1. ブロックがフォルダーへ集まる（初期の第一候補）。可愛いが、保存・移動に見える。
2. Sアプリアイコンが弾む。
3. フォルダーを虫眼鏡で調べる。
4. 虫眼鏡で見つけたブロックがフォルダーへ入る。第4案として保留。こちらも保存・移動の意味が強い。

その後、記録を調べる意味と可愛さを両立するため、DBの巣とレコードひよこの案を採用した。
