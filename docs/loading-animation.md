# 読み込みアニメーション

DBを巣に見立て、レコードを表す赤紫のひよこが顔を出して手前へ跳ね、小さなスキャナーのゲートで正面を向いて立ち止まる。スキャンが完了して光の線が消えてから右向きの横顔に切り替え、歩いて退場する。横向きは片目・右へ突き出すくちばし・手前の羽・左の尾羽を持つ別の輪郭で描き、正面の絵の横滑りに見えないようにする。検査中は淡い光の線が上から下へ走り、スキャン完了時にゲートのランプが緑に光る。次の周回では新しいひよこが巣から出てくる。胸は格子の表ではなく羽毛模様にし、背後の積層したDB円柱で記録との関係を示す。

`RecordLoadingAnimation` のXAML図形とStoryboardで描画する。動画・GIF・画像生成サービス・追加パッケージは実行時に必要ない。ライト／ダークテーマで共通の赤紫とラベンダーを使う。

DBの下側に、温かい茶色の枝・藁を編んだ巣を添え、DBが巣に収まる形にする。巣の奥側はDB本体の背後、手前側はDBの底に重ねる。開口部と紫の積層は残し、ひよこの跳躍・向きの切り替えや1周の長さは変えない。

巣とスキャナーが重ならないようにゲートを右へ離し、スキャン光・ランプ・ひよこの停止位置も合わせる。ひよこはゲート中央で確認され、歩いて描画範囲の外へ出てから次の周回へ移る。アニメーション無効時も同じ中央位置に静止表示する。

## 再生と表示の切り替え

同時に処理がある場合は「DB管理の操作 → ドライブ切り替えなどの表示読み込み → スキャン」の順に表示する。表示読み込みはスキャンの周回途中でも直ちに優先し、見出しと補足文も読み込み側に揃える。途中のスキャン進捗通知で読み込み表示を上書きしない。表示読み込みがすべて終わると、選択中ドライブの現在のスキャン段階へ周回の区切りで戻る。

非選択ドライブのスキャンボタンは、選択を変えずにそのドライブをスキャンする。再度押すとそのドライブだけキャンセルする。非選択ドライブではカード内の進捗だけを更新し、中央のアニメーションは表示しない。スキャン中のドライブを選択した場合にのみ、そのドライブのスキャン表示へ切り替える。

スキャン中は、従来の中央の待機表示を使い、別の進捗エリアやアニメーションを追加しない。読み取り中は薄いディスクからひよこが出て、右側の巣に収まったDBへ歩き、開口部へ飛び込む（1周1.3秒）。集計・保存・結果反映中はレコードを整えてDBへ戻す動きに切り替える。進捗率・ステップ・経過時間も中央の補足文に表示する。既存のひよこの図形を共有する。別ドライブへの移動時は前のドライブのアニメーションを止め、戻ると現在の処理段階を表示する。完了・キャンセル時は周回の区切りで待機表示を閉じる。アプリ終了時は直ちに停止する。

DB管理の履歴削除では、カバンを背負ったひよこがDBから出てきて立ち止まり、こちらを向いて手を上げ、「じゃっ！」と挨拶してから右を向いて歩き去る（1周3.1秒）。正面では肩ひも、横向きでは背中のバッグを描く。ひよことバッグが描画領域の外へ出てから次の周回へ進む。静止表示でもバッグと挨拶のポーズを表示し、ほかのモードには持ち物や手上げを引き継がない。DB最適化では、3羽が位置・向きをばらばらにして吹き出しを交わし、笛と音符・「ピーッ」の視覚的な合図で振り向いて整列する。その後、列を詰めて前から順番に右側のDBへ飛び込む（1周4.9秒）。笛は約2秒表示し、合図への反応・整列・整列後の間を確保する。実際の音は再生しない。ひよこは他のアニメーションと同じ54×68の大きさ・縦横比を維持し、縮小やスリム化は行わない。3羽分の表示領域だけ420×170に広げる。ひよこの正面・横向き・足はすべて共通の `ChickFigure` を使い、最適化用のレコードカードは描画しない。いずれもXAMLの図形とStoryboardで描画する。入れ子の一覧更新でも専用表示を維持し、削除から最適化への切り替えは現在の1周が終わってから行う。処理が完了しても周回の区切りまで表示し、アニメーション無効時は処理に対応する静止画を使う。

単体確認は `run-animation-preview.bat` またはexeの `--animation-preview` 引数を使う。`AnimationPreviewWindow` のみを生成し、`MainWindow`・ドライブ列挙・履歴DBの初期化は行わない。通常アプリやデモとは別の単一起動キーを使う。種類・再生／一時停止・周回終了で停止・静止表示・テーマを切り替えられる。自動描画チェックは `--animation-preview --animation-preview-smoke <出力パス>` で行い、全モードと最適化の各段階を画像に保存する。

| 操作 | 待機表示 |
| --- | --- |
| ドライブ・表示する記録・比較条件の切り替え、初回結果の表示 | 直ちにひよこを表示し、結果をまとめて切り替える |
| ツリーの展開・子フォルダーの追加読み込み | 300ms未満なら表示なし。それ以上は対象行に小さなスピナー。同じ親への重複読み込みは抑止する |
| フォルダー移動、一覧の更新 | 対象の一覧領域だけ操作を止め、300msを超えた場合だけ薄く覆ってひよこを表示。パス・件数・内容は一緒に更新する |
| ランキングの条件変更 | ランキング領域だけで同様にひよこを遅延表示する |
| スキャン | 既存の段階・進捗表示を継続する |

ツリー行のスピナーは完了時に即座に消す。一覧・ランキングのひよこは、再生を始めた場合だけ現在の1周を完走する。300ms未満の操作ではひよこを再生せず、周回待ちも設けない。速い操作の完了後にタイマーで表示が出ないようにし、重なった要求の古い完了で新しい要求の待機表示を消さない。他のツリー行やタブは引き続き操作できる。ドライブなどの全体切り替えでひよこを表示している間は、その内側で局所アニメーションを重複して始めない。

- 1周は1.2秒。顔を出す→跳ぶ→ゲートで正面を向いて止まり、上から下へ走る光の線で確認される→光が消えたら右を向いて歩き出し、退場する。巣へは戻らない。描画範囲の外へ出てから姿勢・位置・光・ランプをリセットし、次のレコードとして再登場する。
- 読み込み中は繰り返す。処理完了後は次の周回を始めず、現在の周回の完了イベントで結果を一括表示する。即時完了でも開始した1周は再生する。
- 重なった読み込みは同じ再生を共有する。最後の処理が完了するまで結果を覆い、新しいドライブ選択などが入れば再生を継続する。
- 通常の処理完了・キャンセル・エラーは同じ周回境界で表示を戻す。ウィンドウ終了時はすぐ停止し、待機中の非同期処理を解放する。
- Windowsのアニメーション効果が無効なら、巣の横にいるひよことスキャナーを静止表示し、周回待ちは設けない。

## プレビュー

Releaseビルド後、PowerShellから次を実行する。デモ専用の待機画面でループを確認でき、実ディスクの読み取りや履歴保存はしない。通常版と同じ管理者確認が出る。

```powershell
Start-Process .\src\Something.App\bin\Release\net10.0-windows10.0.26100.0\win-x64\Something.App.exe -ArgumentList '--demo', '--preview-loading'
```

既存の合成データ用 `--smoke-test <画像パス> --smoke-comparison` は、即時完了時の1周完走、入れ子・重複・キャンセル、連続ドライブ切り替えを検証する。追加の `--smoke-loading` で読み込み中の画面を撮影する。

## 検討した案

1. ブロックがフォルダーへ集まる（初期の第一候補）。可愛いが、保存・移動に見える。
2. Sアプリアイコンが弾む。
3. フォルダーを虫眼鏡で調べる。
4. 虫眼鏡で見つけたブロックがフォルダーへ入る。第4案として保留。こちらも保存・移動の意味が強い。

その後、記録を調べる意味と可愛さを両立するため、DBの巣とレコードひよこの案を採用した。
