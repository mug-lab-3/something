# 容量分析

「ファイル／容量分析／DB管理」の中央タブです。ファイルタブと同じツリーと、戻る・進む・上へ・現在のパスを表示します。ツリーで選択したフォルダの配下にあるフォルダを横断して分析し、フルパス・サイズ・比較中の増減を右側の一覧に表示します。選択したフォルダ自体はリストに含めず、上部のパスで示します。ドライブルートを選ぶとドライブ全体の分析に戻り、配下にフォルダのない場所では0件になります。ダブルクリックは容量分析タブのまま該当フォルダへ移動して分析範囲を絞り込みます。右クリックの開く・パスコピーも維持します。

両タブの現在位置と移動履歴は共通です。ツリーはマウスでもキーボードでも選択を反映します。表示中の記録・属性フィルター・比較条件に対応した取得済みの分析データを範囲で絞り込み、フォルダ選択で再スキャンやDB更新は行いません。範囲は保存された名前のパスを区切り文字込みで比較し、似た接頭辞の別フォルダや大文字小文字が異なる名前を混同しません。並べ替え・最下位フォルダの条件・比較中も同じ範囲を維持し、新しい移動開始後は古い範囲の取得結果を表示しません。

ドライブ、表示する記録、比較する期間・スキャンはファイル画面と共通です。「フォルダのみ」は初期状態でチェックありで、従来通りフォルダだけを表示します。外すと選択フォルダ配下のファイルも再帰的に含め、種類で分けずサイズ・名前・増減の順に並べます。名前列の見出しは「フォルダ」から「名前」、件数はフォルダ数から項目数に切り替えます。「最下位フォルダのみ」はフォルダだけを絞り、ファイルには適用しません。深さ指定・並び順選択欄・件数制限のUIは設けません。列ヘッダーを再度クリックすると昇順・降順が反転します。件数は条件と同じ行の右端に表示し、タブ幅は変えません。

ファイルのサイズは無名DATAの割り当て容量で、ハードリンクは表示可能な名前ごとに計上し、DOS別名は除外します。既存の隠し・システム表示設定はファイル自身と親階層の両方に適用します。未解決容量は不明のまま保持します。ファイルは既定のアプリで開き、コピーは親ディレクトリとファイルまでの2種類、削除は確認後にゴミ箱へ移動する既存の保護ルールを適用します。

ファイルを含める初回だけ、永続化済みの名前別一覧をLINQの一括読み取りで取得し、検証済みの親参照とフォルダパスを結びます。全フォルダに対する個別DB問い合わせは行いません。結果はスキャン単位でメモリに保持し、以後は属性・範囲を絞って再利用します。保存形式やDBは変更せず、再スキャンも行いません。比較は両スキャンの完全な参照（番号とシーケンス）と相対パスで名前を照合し、曖昧なリンクの移動や片側で未観測の項目を0として扱いません。

通常の容量順と比較の増減順のどちらも上位20件の打ち切りを廃止します。条件に一致する分析結果をワーカースレッドで取得・並べ替え、UI用の行モデルは250件ずつ追加します。ListViewの仮想化とスクロールで最後まで表示でき、ページ切り替えは不要です。分析結果自体はメモリに保持するため、初回集計の処理量とメモリは対象フォルダ数に依存します。DBへのページ問い合わせを繰り返して全フォルダ集計をやり直す構造ではありません。ドライブ・履歴・比較条件の変更で無効になった一覧には追加しません。

ルートやNTFS管理領域を除外する既存の方針は維持します。サブフォルダ込みの値なので、親子の行を合計すると重複します。比較中の増減列では正・負・ゼロの行を含めて並べ替えます。増減が不明な行をゼロとして扱わず、昇順・降順のどちらでも末尾に表示します。

CLI等向けの上位N件APIは保持し、アプリ用には件数制限のない分析APIを分けます。DBスキーマや保存済み履歴は変更しません。テストでは600フォルダの全件取得、上位N件API、深さ・最下位条件、キャンセル、差分の20件超の取得、UIの600行スクロール、古い一覧への追加防止、ツリー選択と移動履歴、混在一覧のサイズ順・範囲・差分、属性とハードリンクの集計一致を確認します。
