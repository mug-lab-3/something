# 容量分析

「ファイル／容量分析／DB管理」の中央タブです。ファイルタブと同じツリーと、戻る・進む・上へ・現在のパスを表示します。ツリーで選択したフォルダの配下にあるフォルダを横断して分析し、フルパス・サイズ・比較中の増減を右側の一覧に表示します。選択したフォルダ自体はリストに含めず、上部のパスで示します。ドライブルートを選ぶとドライブ全体の分析に戻り、配下にフォルダのない場所では0件になります。ダブルクリックは容量分析タブのまま該当フォルダへ移動して分析範囲を絞り込みます。右クリックの開く・パスコピーも維持します。

両タブの現在位置と移動履歴は共通です。ツリーはマウスでもキーボードでも選択を反映します。表示中の記録・属性フィルター・比較条件に対応した取得済みの分析データを範囲で絞り込み、フォルダ選択で再スキャンやDB更新は行いません。範囲は保存された名前のパスを区切り文字込みで比較し、似た接頭辞の別フォルダや大文字小文字が異なる名前を混同しません。並べ替え・最下位フォルダの条件・比較中も同じ範囲を維持し、新しい移動開始後は古い範囲の取得結果を表示しません。

ドライブ、表示する記録、比較する期間・スキャンはファイル画面と共通です。列ヘッダーのフォルダ・サイズ・増減をクリックして並べ替え、同じ列を再度クリックすると昇順・降順が反転します。条件は最下位フォルダのみで、深さ指定と並び順の選択欄は設けません。件数制限を選ぶUIも設けません。対象の総フォルダ数は、容量分析画面の「最下位フォルダのみ」と同じ行の右端に表示します。タブには件数を含めず、ドライブ変更時もタブ幅を変えません。

通常の容量順と比較の増減順のどちらも上位20件の打ち切りを廃止します。条件に一致する分析結果をワーカースレッドで取得・並べ替え、UI用の行モデルは250件ずつ追加します。ListViewの仮想化とスクロールで最後まで表示でき、ページ切り替えは不要です。分析結果自体はメモリに保持するため、初回集計の処理量とメモリは対象フォルダ数に依存します。DBへのページ問い合わせを繰り返して全フォルダ集計をやり直す構造ではありません。ドライブ・履歴・比較条件の変更で無効になった一覧には追加しません。

ルートやNTFS管理領域を除外する既存の方針は維持します。サブフォルダ込みの値なので、親子の行を合計すると重複します。比較中の増減列では正・負・ゼロの行を含めて並べ替えます。増減が不明な行をゼロとして扱わず、昇順・降順のどちらでも末尾に表示します。

CLI等向けの上位N件APIは保持し、アプリ用には件数制限のない分析APIを分けます。DBスキーマや保存済み履歴は変更しません。テストでは600フォルダの全件取得、従来の上位N件API、深さ・最下位条件、キャンセル、差分の20件超の取得、UIの600行スクロール、古い一覧への追加防止、ファイル画面への移動を確認します。
