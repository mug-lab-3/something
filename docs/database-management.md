# DB設定と容量表示

設定ボタンから開くモーダルに「表示」と「DB設定」を置く。DB管理タブの上部とDB設定に、全ドライブ共通のDBサイズを表示する。サイズは現行の `catalog-v4.duckdb` とそのWALのファイル長の合計で、ツールチップで内訳を確認できる。移動途中のコピー、旧形式のDB、最適化の作業用ファイルは含めない。

表示時と、スキャン完了・履歴削除・最適化・DB移動・DB削除に伴う再読み込みで更新する。監視や定期更新は行わない。

## 保存先の変更

- 保存フォルダを入力するか「参照」で選び、「保存」を押すと全ドライブの履歴DBを移動する。DBファイル名はストレージ形式に対応する固定名。
- 保存先の設定は `%LOCALAPPDATA%\Something\database-settings.json` に保存する。表示設定とは別に保持し、デモでは通常の設定を読み書きしない。
- スキャン中や読み込み・履歴処理中は保存先変更とDB削除を無効にする。移動前に各ドライブ・比較表示のDB参照をすべて解放する。
- WALをチェックポイントし、空いている保存先へ小さなバッファでコピーする。移動先にDB・WAL・復旧ファイルがある場合は上書きしない。
- コピーの形式を検証してから保存先設定を原子的に更新し、その後で元DBを削除する。コピー・検証・設定保存の失敗時は元DBを使い続ける。設定確定後のキャンセルで検証済みコピーを取り消さない。
- 元DBだけ削除できない場合、新しい保存先を利用し、旧DBが残ったことを警告トーストで伝える。移動元フォルダの無関係なファイルは移動・削除しない。
- コピー中にプロセスが強制終了された場合は元DBと元の設定を保持する。移動先に残る `.moving-*.duckdb` は公開済みのDBとしては扱わない。

再起動は不要。移動後の履歴を読み直し、スキャンと履歴表示は新しい保存先を使う。

## DB全体の削除

設定の「DBを削除」から、全ドライブの履歴を削除する確認ダイアログを出す。キャンセル時は何も削除しない。スキャン対象の実ファイルは削除しない。

確認後はDB参照を解放し、現行DBの形式を確認してからDB本体を削除する。SQLiteや旧形式DB、DBの隣にある他のファイルは削除しない。単独で残ったWALやリンク・フォルダをDBとして削除しない。

表示中の履歴・比較・ツリー・一覧・カードをクリアする。空の履歴を表示するだけではDBを再作成せず、次のスキャン時に新規DBを作成する。

## 検証

`ScanHistoryTests.DatabaseFiles.cs` で容量の内訳、保存先設定、移動・削除、既存DBの保護、参照中の拒否、キャンセル、設定保存失敗、異常なパス・WALの保持を検証する。

`--demo --demo-static --demo-history <専用ディレクトリ>/history --smoke-test <専用ディレクトリ>/app.png --smoke-database-settings` で設定画面・確認ダイアログの描画、削除キャンセル、全ドライブの履歴移動、保存先設定、DB削除後の表示クリアと再スキャンを確認する。合成データだけを使い、専用のhistoryディレクトリ以外ではDB操作テストを拒否する。

フォルダ選択には既存のWindows App SDK 1.8の `Microsoft.Windows.Storage.Pickers.FolderPicker` を使用する。[MicrosoftのAPI説明](https://learn.microsoft.com/en-us/windows/windows-app-sdk/api/winrt/microsoft.windows.storage.pickers?view=windows-app-sdk-1.8)にある、管理者権限で動作するデスクトップ向けAPIを使い、依存パッケージは追加しない。
