# ファイル・フォルダの操作

「ファイル」「容量分析」の一覧の右端に、ゴミ箱へ移動するアイコンを表示します。クリック時に現在の対象を読み取り確認し、存在する同一項目にだけ確認ダイアログを表示します。キャンセルは通常色で、既定の実行ボタンは設けません。フォルダの場合は配下も対象になることを明記します。実行中はひよこの待機表示を継続し、連続クリックによる重複実行を抑止します。

## 保護対象と隠し項目

- システム属性のファイル・フォルダには削除アイコンを表示しません。スキャン時と実行時の両方で判定し、後からシステム属性が付いた対象も拒否します。
- 各ドライブの `Windows` とその配下は、属性にかかわらずすべて削除禁止です。現在のWindowsが標準以外の場所にある場合も実際のWindowsパスと配下を保護します。
- `Program Files`、`Program Files (x86)`、`ProgramData`、`Users`、`Documents and Settings`、`System Volume Information`、`$Recycle.Bin`、`Recovery`、`PerfLogs` のルート直下フォルダ自体を保護します。ユーザープロファイル直下のコンテナ、およびWindowsが返す既知の特別なフォルダ自体も保護します。Windows以外の配下全体を一律に削除禁止にはしません。
- 隠し属性だけならアイコンを表示し、確認ダイアログに警告色でWindows・アプリへの影響を表示します。現在の隠し属性も確認し、警告なしの確認後に隠し属性が付いた場合は中止して再確認を案内します。システム属性との重複は削除禁止を優先します。
- 判定は共通ポリシーをUIと実行側で使用します。一覧の属性は保存済みの観測であり、削除直前には現在の属性で再検証します。フォルダ操作はその中の項目も対象になるため、親フォルダの確認には配下も移動する旨を表示します。

- 存在しなければ確認ダイアログは出さず、右下のトーストで通知します。アクセス拒否などの読み取り失敗は「存在しない」と断定せず、操作エラーのトーストにします。
- ドライブのボリュームGUID、Windows APIで取得するシリアル番号、MFTレコード番号とシーケンス、ファイル／フォルダ種別を照合します。ボリュームGUIDに対応した履歴キーとスキャンのシリアルを保持し、ドライブ文字だけでは判断しません。
- 確認前・確認後・Shellの削除直前に照合します。対象が別の項目に置き換わっていた場合は操作を中止して再スキャンを案内します。
- 相対パス、デバイス・UNCパス、代替ストリーム、ワイルドカード、`.`／`..`、Win32が正規化する末尾ドット・空白、予約デバイス名、NTFS予約レコードは対象にできません。
- 親ディレクトリは再解析ポイントをたどらずに確認し、操作中は削除共有なしの読み取りハンドルを維持します。ジャンクション等を経由するパスは中止します。対象そのものの識別にも再解析ポイントを開くフラグを使います。

実行は専用STAスレッドのWindows [IFileOperation](https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/nn-shobjidl_core-ifileoperation)です。[FOFX_RECYCLEONDELETEとFOFX_ADDUNDORECORD](https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/nf-shobjidl_core-ifileoperation-setoperationflags)を指定し、Shellコールバックがリサイクル以外の削除を示す場合は中止します。アプリに完全削除のフォールバックは設けません。成功判定にはHRESULTと中止フラグだけでなく、[PostDeleteItemのゴミ箱内項目](https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/nf-shobjidl_core-ifileoperationprogresssink-postdeleteitem)も確認します。保護された項目・使用中の項目・ゴミ箱非対応などの失敗はトーストで通知します。

## 取り消し線と履歴

成功した名前に取り消し線を付け、削除アイコンを無効にします。すでに存在しないと確認した名前にも同じ表示を適用します。ハードリンクでは名前とファイル参照の両方で区別し、別の場所のリンクまで削除済み扱いにしません。フォルダの移動ではその配下の表示も対象です。ファイル／容量分析で状態を共有し、並べ替え・フォルダ移動・ドライブ切り替え・後から読み込む行にも反映します。

状態はアプリ内のメモリだけに保持し、再スキャンまたは終了時に破棄します。履歴DB・元の集計・設定別キャッシュは変更しません。サイズや件数はスキャン時の観測のままで、削除直後の実使用量として再計算しません。スキャン取得・NTFS解析は引き続き読み取り専用で、ユーザーが確認したこの操作だけが実ファイルを変更します。

ファイルのダブルクリック・右クリックの「開く」、フォルダを開く際の失敗もトーストで通知します。一覧からフォルダへ移動するときは存在を確認します。ツリーからの保存済み階層の閲覧は引き続きスキャンの観測に基づきます。

照合は楽観的な観測で、VSSのような同一時点の保証ではありません。親ハンドルの保持と実行直前の照合で置換を検出しますが、Shellのパス操作と対象自身の照合を不可分のトランザクションにはできません。フォルダ全体のShell操作が途中で失敗した場合も、移動済みの子が元へ戻るという保証はしません。不明な結果を成功したフォルダとして取り消し線に変えず、残る記録は次のスキャンで確認します。

## 検証

通常のテストでは実データを操作せず、確認キャンセル・確認中の消失／置換・キャンセル・パス検証・ハードリンクの名前単位の状態・配下の反映を偽のバックエンドで検証します。画面テストも`--demo --smoke-recycle`の合成データ専用バックエンドを使い、実行アイコン・ダイアログ・取り消し線・トーストを確認します。確認ボタンの赤色スタイルは履歴削除と共用します。

Windows Shellの実動作テストは`SOMETHING_TEST_RECYCLE=1`を設定して`FileRecycleTests`を実行すると有効になります。GUID付きの一時ディレクトリに自分で作ったファイルとフォルダだけをゴミ箱へ移動し、隣接ファイルと別名ハードリンクが残ること、異なるシーケンスを拒否することを検証します。実ユーザーのファイル・履歴DBは読み書きしません。2026-10-17にこの実動作テストを実行して通過しました。
