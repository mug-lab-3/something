# 履歴の比較と管理

## 識別と保持

履歴はボリューム識別、シリアル、取得範囲、スキャン ID、完了 UTC、記録時のローカル日付と UTC オフセットを保持します。ファイルとフォルダは MFT 番号・シーケンス番号で照合し、番号だけで同一としません。シーケンスの周回をまたぐ長期の同一性は保証しません。

[`HistoryRetention`](../src/Something.Storage/HistoryRetention.cs) の保持規則は次のとおりです。

1. 現在から 7 日未満の完了記録はすべて保持する。
2. それ以前は、ボリューム・記録時のローカル日付ごとの最終記録を保持する。
3. 同時刻の記録はスキャン ID で決定的に選ぶ。7 日ちょうどは全件保持の対象外。

新しいスキャンの保存成功後に整理します。起動時・バックグラウンド監視・定期タイマーによる整理はしません。保存済みのローカル日付を使い、タイムゾーン変更で過去を再分類しません。最大保持日数は設けていませんが、取得以前の履歴は作れません。

## 比較対象の選択

表示するスキャンを終点として、24 時間、7 / 30 / 365 日間、今日、今週、今月、今年、または任意の二記録を比較できます。暦の週は月曜始まりです。プリセットの暦境界は指定タイムゾーンで解決します。

[`ComparisonSelection`](../src/Something.Storage/ComparisonSelection.cs) は終点より未来のスキャンを使いません。期間開始以前の最新記録を基準とし、その記録がなければ期間内で最古の別記録を使います。この場合は履歴がある範囲のみの比較として、要求期間と実際の両端を区別して表示します。

一記録しかない場合はそれを基準側に残し、比較する側を記録なしとします。同じ記録を両端に使って増減 0 と表示しません。任意比較では画面上の矢印に沿って、比較先のサイズから比較元のサイズを引きます。

差分は期間両端のサイズの差であり、期間内の全変化の累積や一時的ピークではありません。同じ識別子の改名・移動は両端のパスを保持します。片側だけの観測、未解決容量、階層の不確実性は、新規・削除や既知の増減と区別します。比較の両端には同じ表示設定を適用します。

## 手動で履歴を削除する

履歴タブは共通のドライブ選択を使い、スキャン日時とレコード数を一覧表示します。ヘッダーのチェックから全選択・解除できます。

日時範囲や期間ボタンは対象範囲の入力を変更するだけです。「この範囲で選択」の適用操作で行のチェックへ反映します。開始・終了は履歴の日時で初期化します。選択した履歴を削除する前に、件数と日時範囲を確認ダイアログに表示します。

削除は履歴データだけを対象とし、実ファイルを削除しません。完了後は関係する表示を読み直し、通知します。閲覧参照が残る共有状態は、その参照の解放後に回収します。

## DB サイズと最適化

履歴タブと設定画面のデータベースのサイズは、現行 DB 本体と WAL のファイル長の合計です。全ドライブ共通で、各スキャンの専有サイズではありません。共有状態があるため、レコード数を単純な容量へ換算できません。旧形式・作業コピー・バックアップはこの表示に含めません。変更を伴う操作と画面読み込みで更新し、常時監視はしません。

通常削除後は `CHECKPOINT` を行います。DB ファイルが削除件数に比例して小さくなる保証はなく、空き領域は後の保存で再利用されます。全体を詰め直す場合は独立した「DB を最適化」、または削除確認内の最適化オプションを使います。時間と空きディスクを要するため、明示操作と確認を必要とします。

[`HistoryCompaction`](../src/Something.Storage/HistoryCompaction.cs) の手順は以下です。

1. 閲覧セッションを解放し、DB ゲートを取得する。残る管理対象接続があれば拒否する。
2. 退役世代を回収してチェックポイントする。日次保持規則での追加の間引きは行わない。
3. 元 DB の 1.25 倍 + 64 MiB の空きディスクを事前確認し、専用作業ディレクトリにファイル DB をコピーする。
4. 全永続テーブルを双方向の `EXCEPT ALL` で照合し、形式・共有関係も再検証してフラッシュする。
5. コピー先が小さい場合だけ、バックアップを伴う `File.Replace` で置き換える。再接続の検証後にバックアップを削除する。

切替前はキャンセル可能です。置換・再検証の短い区間はキャンセルしません。未完了の置換を示す `.compaction-backup` があれば、次の操作で元 DB を復元します。WAL 等が併存する不明な状態を強行して消しません。異常終了では `.compaction-*` の作業コピーが残る場合があります。

コピー・照合はメモリと一時的なディスク書き込みを伴います。成功時にも必ず縮小するとは限りません。削除後の最適化だけが失敗した場合は、削除が済んだことと最適化失敗を分けて通知します。

## 保存先の変更と DB 全体の削除

設定の DB 設定から、保存フォルダの指定・フォルダを開く・DB 全体の削除を行えます。設定は `%LOCALAPPDATA%\Something\database-settings.json` に保持します。表示設定とは分離し、デモは通常の設定を読み書きしません。

保存先変更は全ドライブの履歴を移します。DB 参照を解放し、WAL をチェックポイントした後、移動先へコピーして形式を検証します。設定を原子的に更新してから元 DB を削除します。移動先に既存 DB・WAL・復旧ファイルがあれば上書きしません。設定確定前の失敗は元の保存先を維持し、元 DB の削除だけ失敗した場合は新しい保存先を使って警告します。

DB 全体の削除は確認後に現行形式の DB だけを削除し、表示中の記録をクリアします。空の表示のために DB を即座に再作成せず、次のスキャンで作成します。隣接ファイル、旧 SQLite、旧形式の DB、単独の不明な WAL は削除対象にしません。

スキャン・読み込み・履歴処理中は、移動・全体削除・最適化を開始できません。履歴のバックアップを手作業で取得する場合は、アプリを終了してから DB と存在する WAL を一組として扱い、使用中の本体だけをコピーしないでください。
