# 画面と状態管理

## ドライブとタブ

上部のドライブカードには、総容量・使用量・空き容量とスキャンの状態を表示します。スキャン後は最終スキャン日時を表示し、秒単位の日時・処理時間・件数はツールチップで確認できます。カードは横にスクロールでき、選択中のカードは枠線で示します。カード内のスキャンボタンはそのドライブだけを操作し、選択していないドライブをスキャンしても選択は変わりません。

| タブ | 内容 |
| --- | --- |
| ファイル | ツリーで選んだフォルダーの直下のファイル・フォルダー |
| 容量分析 | ツリーで選んだフォルダー以下をまとめた容量の一覧。既定はフォルダーだけで、ファイルも含められる |
| 履歴 | 選択したドライブのスキャン履歴、範囲での選択、削除、データベース全体の最適化 |

一覧は列の見出しをクリックすると並べ替わり、スクロールに合わせて続きを読み込みます。DB からはページ単位で取得し、表示する件数を上位の決まった件数に限ることはしません。「戻る」「進む」は閲覧の履歴を、「上へ」は親フォルダーへの移動を表します。深いツリーでは、選択した項目が見えるように横スクロールを調整します。

## 表示するスキャンと比較

左に比較の切り替えを置き、その隣に比較元と比較先のスキャンを表示します。スキャンは、スキャンがある日付と一覧を確認しながらダイアログで選びます。比較中もサイズの列はそのまま表示し、一覧に増減の列を追加します。

ツリーには数値を足さず、展開アイコンと名前の間に、増加・減少・比較できないことを示す印を置きます。色だけに頼らず、形とツールチップでも状態を示します。比較期間と欠測の意味は[履歴の仕様](history.md)を参照してください。

## 設定

歯車ボタンで、ドライブカードより下（タブと内容）が設定ページに切り替わります。「←」または Esc で元のタブに戻ります。ドライブカードは表示したままで、設定ページを開いていてもスキャンを開始できます。

左のツリーを目次、右を設定項目の一覧とします。ツリーで選ぶと右の該当箇所へスクロールし、右をスクロールするとツリーの選択も追従します。上部の検索は、項目の見出し・説明と、その上の見出しの文言に一致する項目だけを残します。大文字・小文字、全角・半角、ひらがな・カタカナは区別しません。

表示設定は、チェックを切り替えた時点で反映して保存します。保存・キャンセルのボタンはありません。履歴データベースの移動と削除は、ボタンを押して確認したあと、設定ページを閉じて処理中の表示と完了通知で結果を示します。スキャンなどの処理中は、移動・削除の操作を無効にします。

## エクスポート

歯車ボタンの左にあるエクスポートボタンで、集計結果をファイルに書き出せます。ほかのツールで使うことを想定し、全件ではなく必要な範囲だけを出力します。

| 出力する内容 | 範囲 |
| --- | --- |
| 表示中の一覧 | ファイル タブでは今のフォルダーの中身すべて（まだ読み込んでいない行も含む）、容量分析タブでは一覧のすべて。表示中の並び順のまま |
| フォルダーの集計 | 今のフォルダーと、その配下のフォルダー。深さの上限・最小サイズ・件数の上限で絞り込み、サイズ（比較中は増減も選択可）の大きい順に並べる |

比較中は、比較元のサイズ・増減・比較の状態も出力します。表示設定（隠し・システム）で除外している項目は出力しません。履歴タブでは「表示中の一覧」は選べません。

| 形式 | 内容 |
| --- | --- |
| プレーンテキスト・HTML | 人が読むための形式。日本語の見出しと「1.23 GiB」のような表示で、作成日時などの情報を先頭に付ける |
| CSV・TSV | 表計算やツール向け。英語の列名（`path`、`sizeBytes` など）と、整数のバイト数。Excel で文字化けしないよう、BOM 付きの UTF-8 |
| JSON | プログラム向け。形式名・バージョン・作成日時などの情報と、列の定義、行を持つ。128 ビットのサイズもそのままの値で出力する |
| Parquet | 分析ツール向けの圧縮された列形式（ZSTD）。サイズは 64 ビット整数で、作成日時などはファイルのメタデータに入れる |

ファイルは保存先の隣に一時ファイルとして書き、完成してから置き換えます。途中で失敗しても、書きかけのファイルは残りません。時間がかかる場合は、専用のアニメーション（ヒヨコが頭に乗せた段ボールを軽トラックの荷台に積み、トラックが出発する）を表示します。

> [!NOTE]
> 列名と JSON の構造は、`something-export` 形式のバージョン 1 です。互換性のない変更をするときは、バージョンを上げます。

## 属性と表示設定

設定の「システムファイルとフォルダー」「隠しファイルとフォルダー」は既定で両方オンです。全ドライブ共通の値として `%LOCALAPPDATA%\Something\display-settings.json` に保存します。オフにしても、スキャンや DB に保存する対象は減りません。

ファイルと容量分析の一覧では、テーマに合わせたファイル／フォルダーのアイコンを使います。隠し属性には斜線付きの目、システム属性には盾を重ね、ツールチップと読み上げにも含めます。属性が不明な項目を、通常の項目とは断定しません。

## 切り替えとキャッシュ

ドライブ・世代・比較条件を切り替えるときは、古い表示を部分的に差し替えることはしません。待機の表示にしてから、新しいツリー・一覧・パス・件数をまとめて反映します。途中で新しい切り替えがあった場合は、古い処理の結果で画面を上書きしません。

`ScanSession` は、同じ世代について表示設定ごとの集計をメモリに保持します。何も除外しない場合は保存済みの集計を使い、それ以外の設定では初回に計算した結果を再利用します。全ファイルのストリームをキャッシュすることはしません。ルート一覧の先頭ページも再利用し、ほかのフォルダーの一覧は直近の 1 フォルダー分だけをキャッシュします。

セッションはドライブごとに別で、ほかのドライブから戻ったときはそのドライブのキャッシュを使います。キャッシュは、世代の切り替え、履歴を閉じるとき、データベースの操作のための解放、終了時に破棄します。キャッシュを DB や設定の JSON に書き戻すことはなく、キャンセルした途中の結果も保存しません。

## 待機表示

| 操作 | 表示 |
| --- | --- |
| ドライブ・世代・比較条件の切り替え | 全体の読み込みアニメーション |
| ツリーの展開 | 300 ms 以上かかる場合だけ対象行に小さなスピナー |
| フォルダー移動・一覧更新・容量分析の条件変更 | 300 ms 以上で対象領域に読み込みアニメーション |
| 選択ドライブの取得 | ディスクから DB へ運ぶクレーンのアニメーションと進捗 |
| 履歴削除・DB 最適化・エクスポート | それぞれ専用のアニメーション |
| 非選択ドライブのスキャン | カードの進捗のみ。中央表示は変更しない |

読み込み中の表示は、スキャン中の表示より優先します。すべてのアニメーション（読み込み・スキャン・履歴削除・最適化・エクスポート・起動）は、同じ時間の規則に従います。

| 規則 | 値 | 目的 |
| --- | ---: | --- |
| 表示開始までの遅延 | 300 ms | これより早く終わる処理では何も表示しない |
| 表示後の最低表示時間 | 500 ms | 一瞬だけ表示されるちらつきを避ける |
| 終了時のフェードアウト | 200 ms | 周回の途中で終えても途切れて見せない |

処理が終わったら、最低表示時間を満たした時点で、動きの途中でもフェードアウトします。一周の終わりまでは待ちません。画面全体の読み込みでは、途中の表示を見せないように画面をすぐに覆い、キャラクターと説明文だけを遅延のあとに表示します。領域内の読み込みは、領域側の 300 ms の遅延のあとに覆い始め、アニメーション側では遅延を重ねません。モードの切り替えは、一周の終わりで行います。Windows でアニメーションを無効にしている場合は、同じ遅延と最低表示時間で静止画を表示し、フェードはしません。取り消したときや終了時は、すぐに停止します。

図形は、共通の `ChickFigure`、XAML のベクター、Storyboard で作っています。動画ファイルは使いません。読み込み・スキャン・履歴削除・最適化・エクスポートで同じキャラクターを使い、モードごとに姿勢と小物をリセットします。笛と文字は見た目だけの表現で、音は鳴らしません。アニメーションだけを確認するには `run-animation-preview.bat` を使います。

## 通知と起動

完了と情報はアクセント色のトーストで、警告とエラーはそれぞれの意味に合った色とアイコンで通知します。どの種類もタイトルと本文の 2 行構成です。完了と情報は時間がたつと閉じ、警告とエラーは閉じる操作をするまで残ります。背景は不透明です。操作の対象が存在しない場合も、トーストで通知します。

起動時はスプラッシュ画面で初期化中であることを示し、ドライブカードの履歴の状態をそろえてから、最初のファイル表示に進みます。起動時に自動でスキャンしたり、履歴を整理したりはしません。

多重起動の防止には Windows App SDK の `AppInstance` を使い、ユーザーとログオンセッションごとに登録します。2 回目の起動では既存のウィンドウを前面に出して元のサイズに戻し、既存のウィンドウが応答しない場合も、別の DB を開くインスタンスは起動しません。デモとアニメーションプレビューは、通常版とは別のキーを使います。
