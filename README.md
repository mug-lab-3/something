# Something

**ディスクの空き容量を、どこが使っているのか。どこが増えているのか。**

Something は Windows 向けのディスク容量分析アプリです。NTFS の MFT を使ってドライブをスキャンし、フォルダやファイルの容量を一覧表示します。スキャン履歴を比較して、容量が増え続けている場所を探せます。

## できること

- **容量を調べる** — フォルダツリーとファイル一覧で階層をたどり、容量分析で選択フォルダ以下の大きな項目を探せます。
- **増減を比べる** — 任意の二記録、24 時間・7 日・30 日・365 日、今日・今週・今月・今年の期間でサイズ変化を確認できます。
- **複数ドライブを調べる** — ドライブごとにスキャンを実行でき、進捗確認とキャンセルに対応します。
- **履歴を管理する** — スキャンをローカルに保存し、日時で選択・削除できます。DB の保存先変更と容量の最適化も行えます。
- **整理につなげる** — パスのコピー、Explorer・関連付けアプリで開く操作、確認付きのゴミ箱への移動に対応します。

隠し・システム項目は、表示と集計への包含を設定できます。設定にかかわらずスキャン結果を保持するため、再スキャンせず切り替えられます。

## 動作環境

- Windows x64
- ローカルの NTFS ドライブ
- 管理者権限（起動時に UAC 確認が表示されます）

スキャンはドライブ単位の手動実行です。常時監視や定期スキャンは行いません。

## インストール

[Releases](https://github.com/mug-lab-3/something/releases) から `Something-v<版>-win-x64.msi` を取得して実行します。`C:\Program Files\Something` に全ユーザー向けにインストールされ、スタートメニューに追加されます。インストーラーはまだコード署名していないため、Windows SmartScreen の警告が表示されます。同じリリースの `SHA256SUMS.txt` や `gh attestation verify` で、このリポジトリのワークフローで作られた配布物かを確認できます（[配布手順](docs/deployment.md#github-release)）。

## ソースから試す

Git と VS Code を用意し、`code` コマンドを使える状態で、このリポジトリをクローンします。リポジトリのルートで以下を実行してください。Visual Studio は不要です。

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/setup.ps1 -Open
dotnet build src/Something.App -c Release
```

セットアップは固定 SDK・依存関係の準備と、ビルド・テストを行います。初回はネットワーク接続が必要で、未導入のランタイムにはインストール時の管理者確認が表示されます。

ビルド後、次の exe を起動します。

```text
src/Something.App/bin/Release/net10.0-windows10.0.26100.0/win-x64/Something.App.exe
```

操作感を先に確認する場合は、`run-demo.bat` で合成した三ドライブのデモを起動できます。実ディスクはスキャンせず、専用の履歴にサイズ増減・追加・移動を記録します。

詳しい手順は[開発環境](docs/development.md)、MSI インストーラーの生成は[配布手順](docs/deployment.md)を参照してください。

## サイズと履歴について

表示する「サイズ」はディスク上の DATA 割り当て容量が基準です。フォルダは配下を含み、ハードリンクは名前ごとに計上します。NTFS の管理領域などもあるため、一覧の合計はドライブの使用済み容量と一致する指標ではありません。[集計の詳しい仕様](docs/capacity-accounting.md)を確認できます。

履歴はローカルに保存します。直近 7 日間はすべての記録、それ以前は各日の最終記録を保持します。比較時に期間全体の履歴がなければ、実際に比較できる日時の範囲を表示します。

スキャンによるボリューム取得は読み取り専用です。実ファイルの変更は、確認ダイアログで承認したゴミ箱操作だけです。スキャン中にもファイルは変化するため、取得できなかった容量や比較不能な項目は、不明として扱います。
